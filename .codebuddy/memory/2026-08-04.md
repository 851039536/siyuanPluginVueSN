## everythingSearch 模块新增「空文件夹」筛选开关

需求：增加空文件筛选，且确保不是系统文件导致系统异常（用户确认：显示空文件夹 + 仅筛选展示 + 自动排除系统路径）。

修改 7 个文件：
1. `types/index.ts`：`SearchOptions` 新增 `emptyFoldersOnly: boolean`
2. `types/storage.ts`：`DEFAULT_OPTIONS` 新增 `emptyFoldersOnly: false`
3. `api.ts`：新增 `SYSTEM_ROOT_DIRS` 常量（windows/program files/program files (x86)/programdata/$recycle.bin/system volume information/recovery/boot/perflogs）+ `isSystemPath(fullPath)` 纯函数，用正则 `/^[a-zA-Z]:\\([^\\]+)(?:\\|$)/i` 提取盘符后一级目录名做小写比对，纯字符串判断无 I/O
4. `components/SearchOptions.vue`：行1 开关组新增「空文件夹」Switch（size=xsmall，i18n 键 emptyFolders，标签上方中文注释）
5. `index.vue`：`handleSearch()` 开启时 query 追加 ` empty:`（Everything 语法）；结果过滤 `options.emptyFoldersOnly && item.type === "folder" && isSystemPath(getFullPath(item))` 排除系统路径空文件夹
6. `zh_CN/everythingSearch.json` + `en_US/everythingSearch.json`：各新增 `emptyFolders` 键

关键点：系统路径判断为盘符无关（可同时保护系统盘与非系统盘上的系统目录），且避免误伤 `D:\mywindows\` 用户目录；过滤仅在空文件夹模式下生效，不影响其他搜索行为。行1 开关组已有 flex-wrap，6 个开关自动换行无需改样式。验证：read_lints 0 error。待用户自行验证 lint/i18n:verify/tsc。

## 修复：空文件夹按钮点击后无结果（根因=minSize 大小过滤冲突）

用户反馈：点击「空文件夹」按钮后没有显示相关文件夹。

排查过程：
1. 实测 Everything HTTP 服务监听在 **8989 端口**（非默认 80，用户已配置正确），`empty:` 语法返回 131248 个空文件夹，`type:"folder"` 字段正常
2. 读取用户存储 `everything-search-options`：`minSize: 1`（KB）！`handleSearch()` 中 forceEmpty 分支拼接 query 后又追加了 ` size:>1kb`，而空文件夹 size 必为 0 → 组合查询 `empty: size:>1kb` 返回 0 结果
3. 模拟验证：`empty: size:>1kb` → totalResults 0；`empty:` 单独 → 131248

修复：`index.vue` 的 `handleSearch()` 中，forceEmpty 分支（空文件夹查询）跳过 minSize/maxSize 大小过滤拼接（空文件夹 size 必为 0，大小过滤无意义），else 分支保留原逻辑。

验证：read_lints 0 error；实测修复后 `empty:` 单独查询返回空文件夹。临时测试脚本 `scripts/_test_empty.mjs` 已清理。
