## gitPush 星期分布柱状图高度修复（所有柱子一样高的 bug）

用户反馈：星期分布柱状图所有柱子高度相同，要求修复高度按数值正比显示。

### 根因分析（2 层）
1. **数据层正确**：`aggregateWeekdayStats` 输出 7 项 `{dow, count}`（真实提交数），`weekdayBars` 用 `max = Math.max(1, ...)` 归一化 heightPct，映射逻辑无 bug
2. **CSS 布局层是根因**：`.gpc-weekdays` 设了 `align-items: flex-end`，覆盖默认 stretch → `.gpc-weekday` 高度收缩为内容高度，不再撑满 `height: 72px` → `.gpc-weekday-track`（`flex: 1`）可用高度≈0 → `.gpc-weekday-bar` 的 `height: XX%` 相对 track 百分比无法解析 → 全部塌缩到 `min-height: 2px`，视觉上所有柱子一样高

### 修复（2 个文件）
1. **`CandlestickSection.scss`** — `.gpc-weekdays` 移除 `align-items: flex-end`（恢复默认 stretch 撑满 72px）；`.gpc-weekday-track` 加 `min-height: 0`（允许压缩，防止内容撑开破坏高度基准）
2. **`CandlestickSection.vue`** — `weekdayBars` 的 heightPct 优化：`w.count === 0 ? 0 : Math.max(4, Math.round((w.count / max) * 100))`，零值星期显示 0%（仅 2px 基线），非零值至少 4% 保证可见，高度严格成正比

### 经验教训
- **flex 布局百分比高度链**：父容器若用 `align-items: flex-end/center` 等覆盖 stretch，子项高度变为内容高度，孙级百分比高度全部失效——百分比高度依赖祖先链有"确定高度"，必须保证最外层容器显式高度 + 中间层 stretch/flex 撑满
