### Bug 修复：过滤 .dll 等二进制扩展名后分析无数据显示
用户反馈"过滤了dll，分析没有数据显示"。根因：`git log --numstat` 对二进制文件（.dll/.sdb/.pdb 等）输出 `-\t-\tpath`（无行数概念），`parseFileLines` 中 `parseInt("-")` = NaN 直接 `continue` 跳过 → 二进制文件根本不会进入 `NumstatCommit.files` 列表 → 按扩展名白名单聚合时匹配不到任何文件 → `buildLineRankings` 的 `added+deleted>0` 过滤把所有 0 行数项目/作者剔除 → 排行全空显示"暂无行数数据"。

修复 3 个文件（保持报告视图零影响）：
1. **reportMetrics.ts**：
   - `parseNumstatBlocks(raw, keepBinary=false)` 和 `parseFileLines(lines, keepBinary=false)` 新增可选参数；`keepBinary=true` 时二进制文件 `-` 解析为 0 行并保留在 files 列表，否则跳过（报告视图 `getNumstatLog` 调用不带参，行为不变）
   - `sumProjectLines`/`sumAuthorLines` 返回类型改为 `LineAgg { added, deleted, fileCount }`（新增导出接口），fileCount 统计匹配文件数（二进制 0 行也计入）
2. **ReportOps.ts**：`getCommitStatsLog` 改为 `parseNumstatBlocks(raw, true)`（仅行数统计路径保留二进制）
3. **useCommitAnalysis.ts**：`buildLineRankings` 聚合 Map 类型改用 `LineAgg`，累加 fileCount；保留条件从 `added + deleted > 0` 改为 `fileCount > 0`

效果：选 .dll 过滤后，项目/作者因匹配到 .dll 文件而保留展示（行数 0，+0/−0/净0）；若仓库 git 历史从未提交过 .dll（如在 .gitignore），选 .dll 仍无数据（无匹配文件，符合预期）。lint 0 error。验证（用户执行）：pnpm lint / npx tsc --noEmit。
