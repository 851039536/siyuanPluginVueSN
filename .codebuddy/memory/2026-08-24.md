## 重构：docAnalysis 重名分析链路去冗余（4 点）

审查 StatsView 重名（duplicate）分析链路发现 4 个冗余点并全部修复：

1. **死配置清理**：`types/index.ts` STAT_SECTIONS 中 duplicate 卡片的 `statKey`/`suffixStatKey` 被 `useStatsOverview` 的 `id==="duplicate"` 硬编码分支短路永不生效。方案：扩展 `StatCardDef` — `statKey` 改可选、`resolveValue` 签名升级为 `(stats, ctx: CardValueContext) => number`、新增 `suffixValue`，新增 `CardValueContext { effectiveDupDocs, effectiveDupGroupCount }`。duplicate 卡片改为 `resolveValue`/`suffixValue` 元数据驱动，删除硬编码分支。
2. **过滤单一入口**：`filterDuplicateGroups` 原在 useStatsOverview（显示）与 useDocStats.queryByStatsCategory（下钻）各调一次。现收敛为 `useDocStats` 新增 `effectiveDuplicateGroups` computed 唯一入口，视图层只消费结果。
3. **卡片语义归位**：重名卡片从"大小分布"分区移入 QUALITY_CARDS（质量 Tab，与孤文档并列）；`.card-value.dup` 颜色类已在 StatCard.scss 定义，样式零改动。
4. **判断标准统一**：toolbar 名称排除按钮 `v-if` 从 `stats.duplicateNameDocs > 0` 改为 `effectiveDupDocs > 0`，与 Hero 徽章一致。

另：`DocStats` 删除 `duplicateNameDocs`/`duplicateNameGroups` 冗余字段（可由 duplicateGroups 派生），全局 0 残留引用。

涉及 5 文件：types/index.ts、useDocStats.ts、useStatsOverview.ts、index.vue、StatsView/index.vue。read_lints 0 错误，SQL 保持唯一查询不重复。用户自行验证 lint/i18n/icons/tsc。

**经验教训**：同一文件的多个 replace_in_file 并行调用存在竞态，后续编辑会被覆盖丢失（本次 useStatsOverview.ts 重名区块与 useDocStats.ts return 导出两次丢失，均已二次补回）。同一文件多处修改应串行执行。
