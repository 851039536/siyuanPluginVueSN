## 修复：gitPush 操作日志莫名丢失（flush 覆盖 bug）

用户反馈 LogPanel 操作日志「之前的数据不见了」。根因在 `composables/useOpLog.ts` 的 `flush()`：组件卸载时无条件 `save(opLogs.value)`，而日志加载是惰性的（仅切到 log 视图或执行 git 操作时 `ensureOpLogsLoaded` 才读盘）。若本次运行从未触发加载，`opLogs.value` 仍是初始空数组，卸载时 `flush()` 用 `[]` 覆盖了磁盘上已有的历史日志。

修复：`flush()` 开头加 `if (!loaded) return` 保护（loaded=false 时内存必为空，磁盘历史未被读取，跳过保存）。`debouncedSave` 无此隐患（只在 appendOpLog 内调用，而 append 前必先 ensureOpLogsLoaded）。

其他「日志变少」因素（非 bug）：300 条环形上限（`MAX_OP_LOG_COUNT`，超限只截最旧）；清空按钮有二次确认。已丢失数据无法恢复。

read_lints 0 错误。
