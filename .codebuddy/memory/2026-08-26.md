## 修复 SettingsPanel 平台/重名排除打开显示为空的时序 bug

现象：设置弹窗「平台管理」显示"暂未配置任何平台"，但用户之前有配置（PLATFORM_META 模块级单例非空，数据未丢）。

根因：PlatformSection 与 ExcludeSection 在 `watch(visible)` 打开时从 `props.platforms` / `props.names` 初始化本地副本，而这两处 props 绑定的是 SettingsPanel 的 `draft.platforms` / `draft.duplicateNames`（reactive 副本，初始为空数组）。Vue pre-flush 更新时序中：父 SettingsPanel 的 watch 初始化 draft 与子组件 watch 初始化本地副本在同一轮刷新，子组件先读到 draft 旧空值；draft 更新后子组件 watch 只监听 visible 不再触发 → 永久显示空。

修复：SettingsPanel 模板中 ExcludeSection 的 `:names` 与 PlatformSection 的 `:platforms` 改为**透传原始持久化值**（`props.duplicateNameFilter` / `props.platforms`），draft 仅承担保存聚合职责。HealthSection/QuerySection 为直接响应式绑定（无本地副本）不受影响。

教训：凡「父组件用 reactive 副本初始化 + 子组件打开时从 props 拷贝本地副本」的写法，必须透传原始数据源，否则同一更新周期内子组件读到旧值。

【修正 2026-08-26】透传原始值后用户仍报告"暂未配置任何平台"——**真正根因是初始化 watch 缺少 `immediate: true`**：整个弹窗外层 `v-if="visible"`，首次打开时组件首次挂载、`props.visible` 即初始值 true（无"变化"），watch 默认不触发 → 初始化从未执行。修复：SettingsPanel（draft 初始化）/ExcludeSection（text）/PlatformSection（localPlatforms）三个 `watch(() => props.visible, ...)` 全部加 `{ immediate: true }`。两个修复叠加后彻底解决。教训：`v-if` 控制显隐 + 挂载时需初始化的组件，初始化 watch 必须 immediate。
