## gitPush 提交信息生成修复：AI 未根据全部修改文件生成
- 问题：WorkingTreePanel「生成提交信息」生成的消息只反映首个文件的改动。根因：`CommitMsgGenerator.generateCommitMessage()` 中 `diffSnippet = fullDiff.substring(0, 3000)` 整体硬截断，首个大文件 diff（锁文件/大组件）超限后其余文件改动对 AI 完全不可见；且 prompt 只给 diff 片段、无文件清单、未要求综合判断。
- 修复（仅改 CommitMsgGenerator.ts，调用链零改动）：
  1. 新增 `buildDiffContext()`：按 `diff --git` 分块，每文件均分配额（总预算 `DIFF_CONTEXT_BUDGET = 10000`，与 `getCommitDeepContext` 口径一致），短文件未用满的预算按序回补长文件，截断文件加标注。
  2. stat 命令加 `--stat=200` 防长路径中间省略。
  3. prompt 重构为「变更文件清单（stat）+ 各文件 diff」结构（参考 deepAnalyzeCommitFix 的清单式 prompt），明确要求 type 综合所有文件判断、多文件时提炼共同意图不罗列文件名。
  4. maxTokens 100 → 200。
- 经验：AI 分析多文件 diff 时禁止整体 substring 硬截断，必须按文件分块分配预算，保证每个文件至少一段进入上下文。

## diff 预算统一应用到全部 AI 生成（用户确认"改"）
- gitPush 4 处 AI 生成原预算口径不一致：generateCommitMessage 用可配置预算，generateCommitFix/deepAnalyzeCommitFix 走 getCommitDeepContext 固定 substring(0,10000) 整体截断（无分块），generateStashDescription 无 diff 仅文件名。
- 统一改动：buildDiffContext 从 CommitMsgGenerator 私有方法提取到 gitPush/utils.ts（共享纯函数，与 parseDiffLines/countDiffStats 同区）；WorktreeOps.getCommitDeepContext 加 `budget = 10000` 可选参数——消息头（%B）原样保留不占预算，按 `text.indexOf("diff --git ")` 拆分，diff 部分走 buildDiffContext；两处修正生成调用点传 `ruleConfig.diffContextBudget`。
- 循环依赖评估：WorktreeOps→utils→types/index→GitPushManager→WorktreeOps 形成环，但 buildDiffContext 为函数声明（提升）且仅方法体调用、types/index→GitPushManager 为 re-export live binding，求值安全。
- 结论：现在设置中的「Diff 上下文预算」同时管控暂存区生成 + 单行修正 + 深度分析修正三处；stash 描述不涉及 diff。

## 审查后优化落地（用户确认，计划 0334a762）
- buildDiffContext（utils.ts）引入单文件最小配额 `MIN_PER_FILE_DIFF_BUDGET = 500`：文件数超 `floor(total/500)` 容量时仅取前 capacity 个文件分块（perFile 天然 >= 500，顺带消除 perFile=0 退化），省略数量追加提示「其余 N 个文件 diff 因上下文预算省略」；文件少时行为与均分完全一致。
- getCommitDeepContext（WorktreeOps.ts）消息头拆分由 `indexOf("diff --git ")` 改为 `/^diff --git /m.exec(text)?.index ?? -1` 行首锚定，防提交消息体含该字符串时误截断。
- generateCommitFix/deepAnalyzeCommitFix（CommitMsgGenerator.ts）新增 `buildCommitFileListSection()`：调 `worktreeOps.getCommitFiles`（git show --name-status）生成 `- path（状态中文）` 清单段（rename/copy 显示 oldPath → newPath，状态取 FILE_STATUS_META.title 降级原始 status），插在 prompt「原提交信息」之前——配额省略文件时清单兜底，与 generateCommitMessage 的 stat 清单结构对齐。
- 设计要点：只改策略不改签名，3 处调用点零调整；修正场景每次多一次 git show --name-status 子进程，开销可接受。
