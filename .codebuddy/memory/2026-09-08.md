## gitPush 提交信息生成修复：AI 未根据全部修改文件生成
- 问题：WorkingTreePanel「生成提交信息」生成的消息只反映首个文件的改动。根因：`CommitMsgGenerator.generateCommitMessage()` 中 `diffSnippet = fullDiff.substring(0, 3000)` 整体硬截断，首个大文件 diff（锁文件/大组件）超限后其余文件改动对 AI 完全不可见；且 prompt 只给 diff 片段、无文件清单、未要求综合判断。
- 修复（仅改 CommitMsgGenerator.ts，调用链零改动）：
  1. 新增 `buildDiffContext()`：按 `diff --git` 分块，每文件均分配额（总预算 `DIFF_CONTEXT_BUDGET = 10000`，与 `getCommitDeepContext` 口径一致），短文件未用满的预算按序回补长文件，截断文件加标注。
  2. stat 命令加 `--stat=200` 防长路径中间省略。
  3. prompt 重构为「变更文件清单（stat）+ 各文件 diff」结构（参考 deepAnalyzeCommitFix 的清单式 prompt），明确要求 type 综合所有文件判断、多文件时提炼共同意图不罗列文件名。
  4. maxTokens 100 → 200。
- 经验：AI 分析多文件 diff 时禁止整体 substring 硬截断，必须按文件分块分配预算，保证每个文件至少一段进入上下文。

## buildDiffContext 改为 hunk 均匀采样（用户追加需求）
- 背景：单文件大 diff 超配额时原为 substring 头部截断，AI 只看开头。改为 hunk 均匀采样，保留文件头 + 头/中/尾 hunk，让大文件改动轮廓可见。
- 实现（utils.ts，纯函数）：`sampleDiffChunk(chunk, budget)` 拆分文件头（`indexOf("\n@@ ")`）与 hunk 列表（`split(/\n(?=@@ )/)`），超配额时按 `sampleIndices` 均匀抽取头/中/尾 hunk（`MIN_SAMPLE_HUNKS=3`），每个 hunk 截到 `hunkBudget`（`MIN_HUNK_CHARS=400` 起），省略处插「... 省略 N 个 hunk ...」标记；无 hunk（二进制）回退头部截断。`sampleIndices(n,k)`：k>=n 全取、k=1 取中间、否则首尾必含均匀分布（Math.round）。
- buildDiffContext 主体改造：`pieces` 改为 `{full, quota, truncated}`，quota=截断时 baseQuota 否则 full.length，短文件让出配额按序回补给截断文件（quota 增大后可采样更多 hunk）；截断文件走 sampleDiffChunk。
- 边界：bodyBudget=max(400, budget-header)，sampleCount=max(1, min(3, hunks.length, floor(bodyBudget/400)))，hunkBudget 恒 >= 400，无除零。

## s3Backup 备份运行期渲染崩溃修复
- 现象：触发备份/还原（流式备份）时报 `Cannot read properties of undefined (reading 'backupProgress')`，发生在组件挂载渲染阶段。
- 根因：`BackupProgressSection.vue` 模板用 `{{ i18n.backupProgress }}`，但 defineProps 只声明 progress/phaseLabel 未声明 i18n；父组件 `index.vue`（63-67 行）调用处漏传 `:i18n="i18n"`（同文件其它子组件全传了）。该组件仅 `v-if="isAnyTaskRunning"` 时才挂载，空闲态从不渲染故平时不暴露。
- 修复（2 行）：BackupProgressSection.vue 的 defineProps 增加 `i18n: Record<string, string>`（带注释）；index.vue 调用处补 `:i18n="i18n"`。与 S3ConfigForm.vue 等子组件既有模式一致。read_lints 0。
- 教训：s3Backup 所有子组件一律 props 传 i18n，新增/改动子组件模板引用 i18n 时务必同步声明 + 父传，缺一即运行期崩溃。该 bug 与 vite 8 升级无关，是升级后功能回归验证暴露的既有缺陷。
