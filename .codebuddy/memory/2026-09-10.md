## 追加：S/M/L 档内边距各减 2px（用户「S M L 内间距缩一点点」）

澄清结论：范围＝全部含档位的组件；幅度＝水平与垂直各减 2px。

### -2px 的 Token 映射（关键经验）
全局间距 Token 为 4/8/12/16/20/24px，减 2px 后多数落在**非 Token 值**上。可用映射：
| 原值 | -2px 后 | 写法 |
|---|---|---|
| 4px `$spacing-1` | 2px | `$spacing-2px` |
| 8px `$spacing-2` | 6px | `m.$gap-xs`（_mixins 本地 6px） |
| 12px `$spacing-3` | 10px | `m.$spacing-2_5`（_mixins 本地 10px） |
| 16px `$spacing-4` | 14px | **无 Token**，硬编码 + `// 14px 无对应 Token` |
| 20px `$spacing-5` | 18px | **无 Token**，硬编码 + `// 18px 无对应 Token` |
| 10px `m.$spacing-2_5` | 8px | `$spacing-2` |
| 6px `m.$gap-xs` | 4px | `$spacing-1` |
| 5px（Badge 硬编码） | 3px | `$spacing-px`（=3px） |
| 14px（硬编码） | 12px | `$spacing-3` |
| 18px（硬编码） | 16px | `$spacing-4` |

### 逐组件改动
- **Button**：S `8px 12px`→`6px 10px`、M `8px 16px`→`6px 14px`、L `12px 20px`→`10px 18px`；同时 `gap` S 4→2px、M 8→6px、L 12→10px
- **Input** `.si-input__field`：S `4px 8px`→`2px 6px`、M `8px 12px`→`6px 10px`、L `12px 16px`→`10px 14px`
- **Select**：trigger 与 option 同步减 2px（S `2px 6px`/`2px 14px`、M `6px 10px`/`6px 14px`、L `6px 14px`/`6px 14px`）
- **Card**：header/footer/body 各减 2px（S `8px 10px`/`10px`、M `12px 14px`/`14px`、L `16px 18px`/`18px`）
- **Tag**：S `2px 8px`→`2px 6px`（纵向 2px 已到下限保留）、M `4px 10px`→`2px 8px`、L `6px 14px`→`4px 12px`

### 未改动的组件及原因
- **Slider**：档位差异只在轨道高度与滑块直径，**无内边距可缩**；`__value` 的 min-width 是数值预留宽度，缩小会挤字，故不动

### 5 项真实缺陷（均已核实为真 Bug，非推测）
1. **键盘焦点不可见**：`Button.scss` 只有 `outline: none` 无 `:focus-visible`（全项目 16 个组件 SCSS 中仅 Switch/Select 有）。修复：`&:focus-visible { outline: 2px solid var(--b3-theme-primary); outline-offset: 1px; }`。
   - **经验**：`_mixins.scss` 的 `focus-ring` mixin 只改 `border-color`，而 `.si-button` 的 border 是 `1px solid transparent`、实底变体不设 border-color → **单用该 mixin 在实底按钮上完全不可见**。焦点环要用 outline（同 Switch.scss），不能无脑复用 focus-ring。
2. **loading 时 spinner 压字**：`m.btn-spinner` 绝对居中 + 文案也居中 → 完全重叠。生产实证 `imageCompressor/index.vue:126`（`:loading` + 插槽"压缩中…"）。修复：图标条件由 `v-if="icon && !loading"` 改为 `v-if="icon"`，loading 时对 `__icon`/`__text` 用 `visibility: hidden`（保留占位 → **按钮宽度零跳变**，优于 PrimeVue 的「spinner 替换内容」会塌宽）。

## 追加：Button.vue 冗余与性能审查（用户「审查 Button.vue 是否有冗余，和性能问题」）

### 唯一真实缺陷：`isIconOnly` computed 依赖非响应式的 `slots`
**源码级证据（Vue 3.5.40）**：`node_modules/.pnpm/@vue+runtime-core@3.5.40/.../runtime-core.esm-bundler.js`
- `:5349` `const slots = instance.slots = createInternalObject()`
- `:4882` `const createInternalObject = () => Object.create(internalObjectProto)` → **普通对象，非 reactive**
- `:5341` `assignSlots` 原地 `slots[key] = children[key]`（`updateSlots` 复用同一对象）

→ `computed(() => !slots.default && !!props.icon)` 只在 `props.icon` 变化时重算；插槽增删不触发。而模板 `v-if="$slots.default"`（Button.vue:23）是渲染期实时读取 → **两者会不一致**：
- 初始无插槽（icon-only 方形固定宽高 28px）→ 后出现插槽 → 文字渲染了但 `si-button--icon-only` 还在 → **文字溢出方块**
- 反向：插槽消失但类名丢失 → 不再是方形

**影响面**：全项目**当前 0 处触发**（多行搜索 `<Button[^>]*>\s*<(template|span|IconWrapper|div)[^>]*v-if` 无命中）→ 属潜在缺陷。

**修复**：`buttonClasses` / `isIconOnly` / `accessibleName` 从 `computed` 改普通函数（渲染期必然重算，与模板 `$slots` 读取对齐）；computed 在此处的缓存是**有害的**（缓存了非响应式快照）。

### 冗余（2 项）
1. `disabled || loading` 重复 2 处（模板 `:disabled` Button.vue:7 与 `si-button--disabled` Button.vue:131）→ 可抽 `isDisabled`
2. `handleClick` 的 `!props.disabled && !props.loading` 守卫是**死代码**：原生 `:disabled` 不派发 click + `pointer-events: none`（Button.scss `--disabled`/`--loading`）→ 永不生效。保留作防御无妨

### 性能：无实际问题
`import.meta.env.DEV` 构建期静态替换 → 生产包无 `console.warn` 分支；`@click="handleClick"` 用稳定函数引用（非每次渲染新建箭头函数）；无 watcher / 定时器 / DOM 查询 / 深监听；`useSlots()` 只取引用无开销；`withDefaults` 已正确省略 `severity`/`iconSize`/`title`/`ariaLabel` 的冗余默认值。

### 复用结论
**Vue 的 `slots` 不是响应式**（见上源码证据）——凡「派生值需要跟随插槽增删变化」的场景，必须用普通函数或直接在模板读 `$slots`，不能用 `computed`。已同步到 MEMORY.md。

### 用户决定（2026-09-10）
审查发现的问题（`isIconOnly` computed 陈旧 + 2 项冗余）经确认 **暂不修改**，`Button.vue` 保持现状。属**已知并有意保留**的状态——后续会话不要主动重提或擅自"修复"这三点。

### 组件设计要点
- **原生 input 承载语义**：视觉隐藏的原生 `<input type="checkbox">`（`opacity:0` + 1px + `pointer-events:none`）放在 `<label>` 内，免费获得 Tab/Space 与表单语义；可视方框 `.si-checkbox__box` 纯展示。区别于 `Switch`（无原生等价元素故用 `button + role="switch"`）
- **模式自动解析**：`isGroup = !binary && Array.isArray(modelValue)`；二元模式用 `modelValue === trueValue` 严格相等；分组模式 `indexOf(value) > -1`
- **受控回写防漂移**：`handleChange` emit 后 `nextTick(syncNativeState)` 把 `checked`/`indeterminate` 写回 DOM —— 父级忽略更新时视觉自动回滚
- **`indeterminate` 只能写 DOM 属性**（无 HTML 属性可表达），用 `watch(() => props.indeterminate, ..., { flush: "post" })` + `onMounted` 同步；同时 `aria-checked="mixed"`
- **分组模式返回全新数组**（`filter` / `[...list, value]`），绝不原地 mutate

### 关键设计（可复用结论）
- **成员边框都不在根元素上**：`Input` 在 `.si-input__wrapper`、`Select` 在 `.si-select__trigger`、`DatePicker` 在 `.si-datepicker__wrapper`、`Button`/`Addon` 在根 → 命中成员**内部**元素必须 `:deep()`
- **档位跨组件传递用 CSS 自定义属性**（非 provide/inject）：`InputGroup` 根类按档位输出 `--ig-addon-pad-y/pad-x/font/min-h`，Addon 用 `var(--ig-addon-*, 兜底)` 消费（沿用 `DatePicker.scss` 的 `--dp-*` 范式；Sass 中 CSS 自定义属性值**必须插值** `#{$var}`，否则原样输出变量名）
- **flex 分配**：`Input`/`DatePicker` 用 `flex: 1 1 0`（`flex-basis: 0` 会压制它们自带的 `width: 100%`，否则会撑破容器）；`Select` `0 1 auto` + `min-width: 6rem`；`Button`/`Addon` `0 0 auto`；所有子项 `min-width: 0`
- **`-1px` 重叠必须配 `z-index`**：`> *:hover, > *:focus-within { z-index: 1 }`，否则被重叠遮住的边框在聚焦时缺一段；`DatePicker` 组内 `outline-offset` 归一为 `-1px`、按钮 `:focus-visible` 同理
- **容器禁设 `overflow: hidden`**（`Select` 下拉是 wrapper 内相对定位、未用 Teleport，会被裁剪）；组内成员**禁带 `label`/`hint`/`error`**（FormField 会撑高错位）
- 高度对齐靠 `align-items: stretch` + 边框承载元素 `height: 100%`（`DatePicker` medium 档 min-height 32px ≠ `Input` 36px，必须拉伸）

### ⚠ 本轮最大的坑：插槽子组件**不带接收方的 scope 属性**（初版实现整体失效，已修正）
初版按「父组件 scoped 样式能作用于子组件根元素」写成 `.si-input-group > .si-input { … }`，**规则全部不匹配**。

- **机制**：Vue 的 scoped 属性在运行时由 `createBaseVNode` 取 `currentScopeId`（= 当前**渲染实例**的 `__scopeId`）写入。`<InputGroup><Input/></InputGroup>` 里的 `<Input/>` 由**调用方**组件的插槽函数创建，`withCtx` 会把 `currentRenderingInstance` 切回**插槽归属者**（调用方），故 Input 根元素带的是 `data-v-调用方`，**不是** `data-v-InputGroup`。官方文档侧证：插槽内容默认不受接收方 scoped 样式影响、须用 `:slotted()`，而 slot 内容拿到的是带 `-s` 后缀的 `data-v-xxx-s`，同样说明它没有接收方的裸 scope 属性。
- **正确写法（已实测编译结果）**：把「成员」部分整段放进 `:deep()`，用 `>` 保留直接子语义 —— `> :deep(.si-input)` 编译为 `.si-input-group[data-v-x] > .si-input`；成员**内部**的边框承载元素用后代形式 `:deep(.si-input__wrapper)` → `.si-input-group[data-v-x] .si-input__wrapper`（更耐受成员内部结构调整）。`> :deep(* + *)`、`> :deep(:first-child.si-button)`、`> :deep(:first-child .si-input__wrapper)` 均验证编译正确。
- **这条规则对所有「容器类共享组件包裹其他共享组件」的场景都成立**：只要子组件是**经插槽**进入的，就不能靠 `.容器 > .子组件` 的 scoped 选择器（`FormField` 等直接写在模板里的子组件不受影响）。
- **验证手段（可复用）**：`@vue/compiler-sfc` 的 `compileStyle({ source, filename, id, scoped: true })` 可离线查看 scoped 编译结果。⚠ 必须先经 Sass 展平再喂给 `compileStyle` —— 直接喂嵌套 CSS 会得到错误结论（scope 属性会被注入到内层选择器开头）。本次用 `node -e` + 自定义 importer（把 `@/` 映射到 `src/`、并回退 `_` 前缀 partial）把 `InputGroup.scss` 端到端编译成最终 CSS 逐条核对，输出全部锚定在 `.si-input-group[data-v-grp]` 上，确认无误。

### 预览框架的取舍
- 用 `<SlotRenderer>`（`defineComponent` 声明 props）而非让 `render` 返回整个 VNode 再 `<component :is="vnode">`：前者不依赖「VNode 作为 `is`」的隐式语义。代价是 SlotRenderer 定义在 `<script setup>` 内、每次渲染重建（预览面板静态、无状态损失，可接受）
- `props` 与 `render` 示例并存时 `resolveProps(example)` 会被调用两次（纯函数、开销可忽略），换取模板无局部变量
