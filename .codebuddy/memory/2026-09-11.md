### 追加：横向布局（用户当日追问「怎么只有竖向的，横向的呢」）

上次澄清时用户选了「裁剪掉 horizontal」，交付后立刻追问要横向 ⇒ **澄清选项里的「裁剪」不等于用户最终不要，交互式选项的排除项要留一句确认口**。补 `layout` 支持：

- **一根 `--reverse` 机制复用两个方向**：`isReversed(index)` 分向判断（竖向看 `right`、横向看 `bottom`，`alternate` 都看奇数索引），CSS 侧只换方向值——竖向 `row-reverse`、横向 `column-reverse`。**反向选择的依据必须按轴判断，否则横向写 `row-reverse` 只会把三块左右翻转**。
- 横向 CSS：根 `<ol>` 变 `display: flex; flex-direction: row`（事件等分宽度），`<li>` 变 `column`；分隔行 `flex-direction: row`（节点在左、连接线向右 `flex: 1` + `height: 2px` + `width: auto` 覆盖竖向的 `width: 2px`）；两侧块的 `padding-bottom` 归零、`text-align` 统一左对齐（竖向的「贴线对齐」在横向无意义）。
- **横向的连线对齐是这套实现的唯一软肋**：列高由各列内容决定（`align-items: stretch` 保证列等高），两侧块各占列高一半 ⇒ 分隔行落在垂直中线、节点跨列对齐；但若某列 `opposite` 更高（换行行数不同），该列会被自己内容顶高，连线呈阶梯状（**与官方实现同病**）。示例特意用等长短文案（`COMPACT_EVENTS`），并在 `componentPreview/README.md` 写明「需要严格水平对齐时让 `opposite` 等高或留空」。想彻底解决只能上 `display: contents` + 跨列 grid/subgrid，代价是 `<li>` 语义与可访问性风险，故不做。
- 示例 9 → 13 例：新增「横向 - 内容居下（`align="top"`）/ 内容居上（`align="bottom"`）/ 上下交错（`alternate`）/ 自定义节点」。`previewData/timeline.ts` 339 行（与既有 `control.ts` 339 行持平，未超同类文件规模）。组件 111 行 / 样式 145 行。

## 新增共享组件 Panel（第 29 个公开组件，同日）

### 官方契约（d.ts + Context7 两源一致）

Props：`header?: string`、`toggleable?: boolean`（false）、`collapsed?: boolean`（false）、`toggleButtonProps?`（默认 `{ severity:'secondary', text:true, rounded:true }`）。插槽 6 个：`default`、`header`（作用域 `{ id, class, collapsed }`）、`icons`、`togglebutton`（`{ collapsed, toggleCallback, keydownCallback }`）、`toggleicon`（`{ collapsed }`）、`footer`。事件 2 个：`update:collapsed`、`toggle`（`{ originalEvent, value }`）。PT 含 `transition` ⇒ **官方默认有高度折叠动画**。

### 落地要点（本项目相对官方的三处有意差异都要记住）

1. **不提供 `toggleButtonProps`**：`object` 型 props 袋在本项目无法既宽又安全地类型化（`h(Button, props)` 拿不到合法类型），改由**官方同样存在的 `togglebutton` 插槽**覆盖同一需求（可放任意共享 `Button`，能力更强）。
2. **`header` 插槽作用域只给 `{ collapsed }`**：官方的 `id` / `class` 分别是其内部 id 与图标字体类名，本项目用 `IconWrapper` + IconKey，提供会误导。
3. **折叠用 `v-show` 瞬时收起 + 切换图标 0.12s 旋转，不做官方的高度动画**：不引 JS 测高、不用 `grid-template-rows: 0fr/1fr`（兼容面 + a11y 复杂度），且 `v-show` 保留内容 DOM（表单状态不丢）并让收起后的内容**退出 a11y 树与 Tab 序列**（比 `aria-hidden` + 可见性 hack 稳）。

### 关键实现技巧

- **受控/非受控双模式**：`collapsed` **刻意不给默认值**，用 `props.collapsed === undefined` 判定是否受控，非受控时写内部 `ref`（与 `SpeedDial.visible` 同范式）。**顺带得到一个好效果**：预览里不传 `collapsed` 的示例可**真实点击折叠**（预览框架只识别 `modelValue`，`:collapsed` 不受其管控）；传了 `collapsed` 的示例则是受控但无监听的静态快照 —— 示例按此分两类并注明。
- **`toggleable=false` 时必须忽略 `collapsed`**：渲染条件写 `v-show="!toggleable || !isCollapsed"`，否则「传了 `collapsed` 没开 `toggleable`」会得到一个永远打不开也没有按钮的面板。
- **图标-only 的 `Button` 不能传默认插槽**（`isIconOnly = !slots.default && !!icon`，读 Button.vue 源码确认）⇒ `toggleicon` 插槽必须走 `v-if/v-else` 双分支，否则会毁掉纯图标按钮的尺寸与布局（与 ToggleButton 的已知陷阱同源）。
- 旋转动画**加在按钮本体**而非用 `:deep` 穿透 Button 内部（纯图标按钮为圆形，旋转按钮 ≡ 旋转图标）；自定义图标分支不加该类，避免把调用方的文案一起转。
- 无障碍：`useId()` 生成 `titleId`/`contentId` 对（`Listbox` 已有先例），切换按钮 `aria-label`（`toggleLabel` prop + 中文默认值 ⇒ **零 i18n 分片改动**）+ `aria-expanded` / `aria-controls`，内容区 `role="region"` + `aria-labelledby`（无标题时不下发该属性，避免悬空引用）。
- 收起时去掉头部下边框（`&--collapsed &__header { border-bottom: none }`），否则边框悬在空白处。
