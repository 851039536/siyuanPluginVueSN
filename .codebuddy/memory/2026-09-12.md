## 新增共享组件 Message（参考 PrimeVue Message）
- 需求与拍板：参考 https://primevue.dev/message/ 新增通用组件。`severity` **照搬官方取值**（`secondary`/`success`/`info`/`warn`/`error`/`contrast`，与库内 `Button.severity` 的 `warning`/`danger` **有意不统一**）；做 `closable` + `life`，**不做** `variant`（outlined/simple）；本次只新增组件，不顺带迁移 feature 内既有自建提示。
- 交付：`src/components/Message.vue`（161 行）+ `styles/Message.scss`（约 150 行）+ `previewData/message.ts`（13 张示例卡，`sizeable: true`）+ `previewData/index.ts` 聚合（`...messagePreviewGroups` 插在 tagAvatar 之后）。
- 关键实现决策：
  1. **不自动隐藏**：点击关闭与 `life` 到期都只派发 `close(MouseEvent | null)`，是否移除由调用方 `v-if` 决定（同 `ConfirmDialog`「confirm 后不自动关闭」范式）—— 已登记进 AGENTS.md 组件行与 componentPreview README「事件契约」表。
  2. **关闭按钮复用共享 `Button`**（icon-only，覆写 `--button-size` 为 18/20/22/24）⚠️ **必须同时写 `min-height: 0`**：Button 档位类自带的 `min-height: 28/36/44px` 会反过来决定高度，只改 `--button-size` 完全无效（下文有实例）。
  3. 插槽名用 **`closebutton`**（作用域 `{ closeCallback }`，经 computed + `v-bind` 传递，同 `Dialog`）而**非官方 `closeicon`** —— 依 AGENTS.md 已登记的「同类语义全库只有一个名字，优先于字面对齐官方」。
  4. `life` 用组件内原生 `window.setTimeout`（库内 `tooltip`/`megaMenu`/`sidebar`/`tieredMenu` 同范式），**不用 `@/utils/timerRegistry`**（组件库需可整目录外迁、零业务耦合）；三条清理路径 = 到期 / 手动关闭 / `onBeforeUnmount`。
  5. `icon` prop 与 `icon` 插槽都不传则**不渲染图标**（与官方一致：`severity` 不自动附带图标，预览必须显式传 `icon` 才看得到）。
  6. 预览清单里的 `icon` 插槽示例**不给 `IconWrapper` 传 `size`** ⇒ svg 取 `1em` 随消息档位字号自动缩放，从而**不必在 previewData 复制组件内部的档位图标尺寸表**（避免同一常量两处定义）。
- 文档同步（实测基线：**47 公开组件 / 54 个 styles（含 2 partial + index）/ 15 私有目录 + 3 支撑目录 / 32 个 previewData / 155 个文件**）：`AGENTS.md`（4 处总数 + TieredMenu/Sidebar 行内埋藏数字 + 新增组件行 + 复用清单补「内联消息提示」）、`componentPreview/README.md`（总数 + 覆盖清单 + sizeable 清单 + 档位段 + 2 行插槽 + 1 行事件 + 新增功能段）、`kit/README.md`、`kit/theme.ts` 注释、根 `README.md` 目录树、迁移指南（3/6/62-64/109/147，并补全 7 个漏登记的组件与 4 个漏列的私有目录）。

## 修复 FileUpload 移除按钮（顺带发现，**此前诊断有误，已纠正**）
- 我上一轮报的「只覆写 `--button-size` 没清 `min-height` ⇒ 呈椭圆」**只对了一半**。真正根因更深：`fileUpload/FileList.vue` **恒定**把 `fileremoveicon` 插槽出口渲染进 `<Button>`，使 Button 的 `$slots.default` 恒真 ⇒ `isIconOnly` 为假 ⇒ **`si-button--icon-only` 类从未输出**，整个 `--button-size` 覆写块是**死代码**（按钮实际是 ~36×28 的带框文本按钮 + 一个空的 `.si-button__text`）。推测是后加 `fileremoveicon` 插槽时引入的回归。
- 关键验证（临时脚本 `tmp-slot-compile-check.mjs`，已删）：用 `vue/compiler-sfc` 的 `compileTemplate` 实测 `<template v-if="$slots.x" #default>` 的编译产物 → `createSlots({_:2}, [ cond ? { name: "default", fn: withCtx(...) } : undefined ])`，即**插槽是条件注册的**，不传时 `slots.default` 真的不存在。
- 修法：
  1. `FileList.vue`：插槽出口改为 `v-if="$slots.fileremoveicon"` **条件转发**（恢复纯图标形态；提供插槽时才走文本形态）。
  2. `FileUpload.scss`：把几何量直接锁在 `.si-fileupload__remove.si-fileupload__remove` 上（`width/height: var(--si-fu-remove)` + `min-height: 0` + `padding/gap: 0`），不再依赖 `si-button--icon-only`；新增档位变量 `--si-fu-remove`（root 兜底 22px、四档 20/22/24/26，与文档数字一致，放在既有档位变量块内）；另加 `:deep(.si-button__text){justify-content:center; &:empty{display:none}}` 处理文本形态下的空文本层与居中。
  3. 文档同步：`AGENTS.md`（FileUpload 行）与 `componentPreview/README.md`（FileUpload 段 + 具名插槽表 `fileremoveicon` 行）补上「清 `min-height`」「尺寸锁自有类」「插槽须条件转发」三条。
- 作用域核实（易错点）：`styles/FileUpload.scss` 被 **3 个** `.vue` 同时 `@use`（`FileUpload.vue` / `fileUpload/FileList.vue` / `fileUpload/ChooseArea.vue`），各自带自己的 scope attr ⇒ 规则能命中子部件模板里的元素（`.si-fileupload__remove` 带的是 `data-v-filelist`）。
- 验证：`npx sass` 编译通过（`.si-fileupload__remove.si-fileupload__remove{...}` 与 `:deep()` 规则均按预期输出）；`read_lints` 0；`previewData/fileUpload.ts` 未使用该插槽 ⇒ 预览快照走纯图标形态，档位切换可目视回归。
