## shortcut 面板「点击删除没反应」修复

- **根因**：`ShortcutManager` 是模块级单例（`new ShortcutManager()` 存模块变量），内部 `shortcuts` 数组**非响应式**；`index.vue` 的 `filteredShortcuts / totalCount / tabs / getTabCount` 用 `computed(() => manager.getAllShortcuts())` **直接读 Manager** ⇒ computed 没有任何响应式依赖，值被永久缓存。删除时 Manager 内部 `splice` + `saveAll` 落盘都成功（数据真的删了），但列表与计数不会重算 ⇒ 卡片不消失、看着像"没反应"（新增、编辑同理不刷新）。
- **事件链核对无误**（不是事件没接上）：`ShortcutCard` emit `delete(shortcut.id)` → `ShortcutGrid` 转发 → `requestDelete` → 共享 `ConfirmDialog`（`@confirm`/`@cancel` 与当前 API 一致，`2814fef8` 迁移到共享组件时改对了；遮罩 `position: fixed` 与旧的本地实现一致）。
- **修法（3 文件）**：
  1. 新增 `src/features/shortcut/utils.ts` —— 纯函数 `searchShortcuts(list, keyword)`（大小写不敏感，空关键词返回 `[]`）
  2. `manager.ts` —— `search()` 改为委托 `searchShortcuts`（消除复制，行为不变）
  3. `index.vue` —— 新增响应式镜像 `const allShortcuts = ref(manager.getAllShortcuts())` + `refreshShortcuts()`；`totalCount / tabs / getTabCount / filteredShortcuts` 全部改读该 ref；`confirmDelete()` 与 `addShortcut()` 成功后调用 `refreshShortcuts()`；`onMounted` 末尾（await 收藏/最近之后）再刷一次，覆盖「面板先于 `initShortcutData` 异步载入时挂载」的时序。
- **验证**：`read_lints` 0 条；`pnpm typecheck`（vue-tsc）全仓库 0 error。
- **可复用结论**：任何「面板 computed 直接读单例 Manager」的模块都有同一隐患；正确模式 = 视图层 `ref` 镜像 + 变更后 `refresh()`（gitPush `useProjectCrud.loadProjects()` 即此模式）。

### 修复：新增窗体点一下即消失（共享弹层外壳潜伏 bug）

- **现象**：点击「+ 新增」打开 `ShortcutDialog` 后，点进任意输入框的第一下弹窗就关闭。
- **根因**：`src/components/overlay/useOverlay.ts` 的遮罩点关判定只比较「`mousedown` 目标 === `mouseup` 目标」，**没有校验目标是否为遮罩本体**。弹层内部任意点击（点输入框、点文案）两个目标都是同一个内部元素 ⇒ 被判成「点了遮罩」⇒ `onDismiss()` ⇒ `update:visible(false)`。长期潜伏的两个原因：`Dialog.dismissableMask` 默认 `false`（本次为表单开了它才踩到），而 `ConfirmDialog` 里任何点击本来就会关闭弹窗。
- **连带发现（更严重）**：`ConfirmDialog` 的确认按钮也会走这条路径 —— `mouseup` 先于 `click` 触发遮罩点关 ⇒ 先 emit `cancel`（调用方 `cancelDelete()` 把 `deleteConfirmId` 清成 null）⇒ 再 emit `confirm` 时读到 null 直接 return ⇒ **删除完全失效**。这解释了用户最初的「点击删除没反应」：除已修的「列表非响应式」外，还有这条**确认回调被提前清空状态**的硬不执行。
- **修法**：`handleMaskMouseDown` 仅当 `event.target === event.currentTarget`（即遮罩本体）时记录目标；`handleMaskMouseUp` 同样要求抬起点落在遮罩本体上。三个消费方（`Dialog` / `ConfirmDialog` / `Drawer`）都把这两个 handler 挂在遮罩 div 上，故 `currentTarget` 恒为遮罩 ✓；行为变化仅限「弹层内部点击不再误关」，`dismissableMask: false` 的用法完全不受影响。
- **文档核对**：`componentPreview/README.md`（对话框段）早已写明「需在遮罩上按下并抬起才算数，弹层内按下、遮罩上抬起不误关」—— 该表述原先与实现不符，修复后才真正成立，无需改文档。
- 验证：`read_lints` 0、`pnpm typecheck` 0 error。
