# 2026-09-14

## shortcut 面板「点击删除没反应」修复

- **根因**：`ShortcutManager` 是模块级单例（`new ShortcutManager()` 存模块变量），内部 `shortcuts` 数组**非响应式**；`index.vue` 的 `filteredShortcuts / totalCount / tabs / getTabCount` 用 `computed(() => manager.getAllShortcuts())` **直接读 Manager** ⇒ computed 没有任何响应式依赖，值被永久缓存。删除时 Manager 内部 `splice` + `saveAll` 落盘都成功（数据真的删了），但列表与计数不会重算 ⇒ 卡片不消失、看着像"没反应"（新增、编辑同理不刷新）。
- **事件链核对无误**（不是事件没接上）：`ShortcutCard` emit `delete(shortcut.id)` → `ShortcutGrid` 转发 → `requestDelete` → 共享 `ConfirmDialog`（`@confirm`/`@cancel` 与当前 API 一致，`2814fef8` 迁移到共享组件时改对了；遮罩 `position: fixed` 与旧的本地实现一致）。
- **修法（3 文件）**：
  1. 新增 `src/features/shortcut/utils.ts` —— 纯函数 `searchShortcuts(list, keyword)`（大小写不敏感，空关键词返回 `[]`）
  2. `manager.ts` —— `search()` 改为委托 `searchShortcuts`（消除复制，行为不变）
  3. `index.vue` —— 新增响应式镜像 `const allShortcuts = ref(manager.getAllShortcuts())` + `refreshShortcuts()`；`totalCount / tabs / getTabCount / filteredShortcuts` 全部改读该 ref；`confirmDelete()` 与 `addShortcut()` 成功后调用 `refreshShortcuts()`；`onMounted` 末尾（await 收藏/最近之后）再刷一次，覆盖「面板先于 `initShortcutData` 异步载入时挂载」的时序。
- **验证**：`read_lints` 0 条；`pnpm typecheck`（vue-tsc）全仓库 0 error。
- **可复用结论**：任何「面板 computed 直接读单例 Manager」的模块都有同一隐患；正确模式 = 视图层 `ref` 镜像 + 变更后 `refresh()`（gitPush `useProjectCrud.loadProjects()` 即此模式）。

- **变更规格**：`docs/shortcut-refactor-spec.md`（AC-01~AC-14 验收清单、迁移算法、冲突判定口径、任务分解）。
- **UI**：2 列卡片网格 → 单列紧凑行式列表。`ShortcutRow`（108px 按键徽章列固定宽保证纵向对齐 + 名称/描述 + 分类 Tag + 冲突警示 + 操作按钮，按钮默认半透明、悬停/聚焦显形）；`ShortcutList`（分组 + 吸顶组头 + 会话级折叠 + 空态走 `IconWrapper`）；`PanelHeader`（两行共享 `Toolbar`：搜索/分类/新增 + 收藏·最近·冲突/计数/导入·导出·重置）；`ShortcutDialog` 改用共享 `Dialog`（字段级必填校验）。**删除** `ShortcutGrid.vue` / `ShortcutCard.vue` 及其 SCSS。
- **持久化三键分离**：`plugin-shortcuts-custom`（唯一可写）＋ `plugin-shortcuts-favorites` ＋ `plugin-shortcuts-recent`；旧键 `plugin-shortcuts-all` 仅作一次性迁移源。迁移守卫用「新键 `exists()`（含空数组）」而非「新键非空」——否则用户删光自定义项后旧数据会复活；**写新键成功才删旧键**，失败保留待下次重试。预置判定改为 id 集合 `isPreset`（视图不渲染编辑/删除 + Manager 拒绝写入，双层设防）。

### 追加：列表改 2 列卡片（CR-002，同日）

- `ShortcutList` 分组内容区改 `grid-template-columns: repeat(2, minmax(0, 1fr))`（`align-items: stretch` 同行卡片等高）；`ShortcutRow` 由横向 4 列行式改为**纵向两行卡片**：上行 = 按键徽章 + 行内操作，下行 = 名称 + 平台标签 + 冲突警示 + 描述（与名称同行、次级色省略）。

- 卡片内不再重复与组头同名的工具标签（`showToolBadge(shortcut, group.name)` 做标签与组名比对——预置数据的 `group` 与工具名完全一致）；收藏卡把徽章底色改回 `--b3-theme-background`，否则与卡底同色不可辨。
- 规格与文档同步：`docs/shortcut-refactor-spec.md` 追记 CR-002；模块 README 的 UI 段改为 2 列卡片，并说明 `ShortcutRow` 未复用共享 `Card` 的原因（紧凑卡片需逐项覆写，会与 Card 自身 scoped 样式打 (0,2,0) 特异性官司 ⇒ 属规范允许的「纯展示的局部布局容器」例外）。
