## 用户需求

审查并优化 `src/features/generalSettings/utils/styles.ts` 中 `applyCodeBlockCollapse` 函数（212-459 行）注入的「代码块折叠」脚本。

## 优化范围

- **冗余消除**：scroll 绑定逻辑重复、双重防抖、isMobile 重复计算、共享 debounceTimer 隐患、冗余的 let 声明
- **性能优化**：DOM 去重守卫提前、scroll 监听 passive、rAF 轮询超时保护
- **不改动**：MutationObserver 的 body 全 subtree 观察范围（收窄风险高）、CSS 部分（231-281 行）、函数签名与调用方

## 功能边界

保持「超过指定高度自动折叠 + 右下角展开/收起按钮」现有行为完全不变，仅做内部实现精简与性能提升。修改仅限 `styles.ts` 单文件。

## 技术栈

- 目标代码：`styles.ts` 中注入的 IIFE 原生 JS 字符串（非 TS 源文件，运行于思源页面 DOM 环境）
- 约束：注入脚本保持自包含、可独立运行，不依赖外部闭包变量

## 实现方案

### 冗余消除

1. **提取 `bindScroll(protyle)`**：将 `initCodeBlockCollapse` 与 `observeProtyleAddition` 回调中重复的 scroll 绑定逻辑合并为单一函数，消除重复代码。
2. **移除 `running` 锁**：删除 `addCodeExtends` 顶部的 `running` 标志与 `setTimeout 300ms`。该锁在 `forEach(async)` 前同步置位、300ms 后盲目解除，与 async 不同步，无实际防并发作用；外层 scroll debounce 100ms 已足够。
3. **缓存 `isMobile` 结果**：在脚本顶层计算一次 `const mobile = isMobile()`，替换两处 `isMobile()` 重复调用。结果在脚本生命周期内不变。
4. **独立 `debounceTimer`**：`bindScroll(protyle)` 内部声明自己的 `debounceTimer`，修复当前两个绑定闭包共享同一 `debounceTimer`、多个 protyle 互相 `clearTimeout` 的隐患。
5. **`let` 改 `const`**：`scrollContainer` 从不重新赋值，改为 `const`。

### 性能优化

6. **去重守卫提前**：`addCodeExtends` 中 `.code-collapse-bar` 守卫从 `await whenElementExist` 之后移到函数最前。已处理的代码块不再走 `isCursorInCodeBlock`、`await whenElementExist`、`querySelector('.hljs')`、`scrollHeight` 读取，显著降低每次 scroll 的开销。
7. **scroll passive**：`addEventListener('scroll', handler, { passive: true })`，避免阻塞滚动。
8. **rAF 轮询超时**：`whenElementExist` 增加超时上限（如 5000ms），超时 `resolve(null)` 而非 reject。调用方已有 `if(!hljs || ...) return` 与 `if(!protyle) ...` 逻辑自然兼容，无需引入 try-catch，避免元素永不出现时无限空转。

### 不改动（风险控制）

- `MutationObserver` 观察 `body` 全 `subtree`：收窄需评估思源 DOM 结构，默认不改，避免引入功能回归。
- CSS 部分、`bar.innerHTML`、按钮 onclick、`isCursorInCodeBlock`、`getCursorElement`、清理事件逻辑保持不动。
