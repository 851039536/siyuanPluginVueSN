## 已修复：收藏切换的并发竞态

### 复现

`toggleFavorite` 由列表项与侧栏两处点击入口直连，可被快速连点。
构造「两次点击的保存同时在途、第一次失败」后用原实现实测：

```
点击 A、B（均在途）→ 结算后
  内存态   = []            ← 回滚到「点击 A 之前」的快照，把 B 也一并抹掉
  持久化态 = ["A","B"]
```

即：**用户看到收藏全部消失，且 UI 与存储不一致**。比 OCR 描述的
「两次点击互相覆盖」更严重（不是覆盖，是整体清空）。

### 修复

`useDiskBrowser.ts` 的 `toggleFavorite` 三处改动：

1. **按项回滚**：失败时只撤销本次点击那一项（按 `path` 反向操作），
   不再整体赋回「点击前快照」，避免殃及并发期间的其它变更。
2. **保存串行化**：用 `saveQueue` 链式排队，同一时刻至多一个 save 在途；
   每次落盘的都是「当前最新」列表，使存储收敛到内存的最终状态。
3. **回滚后补写**：回滚改变了列表，需把修正后的列表重新落盘 ——
   否则失败的那次 save 可能已把「含该项」的列表写入存储，留下一个已被
   回滚的收藏（实测此场景下内存与存储会残留不一致）。

### 修复后验证

模拟保存延迟与指定次序失败的 7 个场景，全部满足「内存在途保存并发恒为 1」+
「内存与存储最终一致」：

| 场景 | 内存 | 存储 | 一致 |
| --- | --- | --- | --- |
| 2 次点击，第 1 次保存失败 | `["B"]` | `["B"]` | ✅ |
| 2 次点击，第 2 次保存失败 | `["A"]` | `["A"]` | ✅ |
| 2 次点击，均成功 | `["A","B"]` | `["A","B"]` | ✅ |
| 3 次点击，第 2 次失败 | `["A"]` | `["A"]` | ✅ |
| 3 次点击，第 1、3 次失败 | `[]` | `[]` | ✅ |
| 单次点击，保存失败 | `[]` | `[]` | ✅ |
| 取消收藏且保存失败 | `[]` | `[]` | ✅ |

修复前跑同一组场景，前两行分别为 `[]`/`["A","B"]`（不一致）。
