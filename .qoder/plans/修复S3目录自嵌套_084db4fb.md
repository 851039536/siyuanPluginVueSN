# 修复 s3FileManager 目录自嵌套 bug

## 问题现象
双击进入 `test/` 文件夹后，列表中又出现一个 `test` 文件夹，双击它仍停留在同一目录，形成无限自嵌套。

## 根因
- `src/utils/s3/s3ObjectOps.ts` 的 `listDir`（L46-48）将服务端 `CommonPrefixes` 原样收入 `folderSet`，未排除等于查询 `prefix` 自身的回显项（OpenList/Alist 类非标准代理会回显）。文件通道（Contents）已有 `key !== prefix` 过滤，文件夹通道没有对等防护。
- 次要：`src/features/s3FileManager/utils.ts` 的 `aggregateEntries` 遇到双斜杠异常键（如 `test//xxx`）时首段为空串，会聚合出 `test//` 前缀，`nameFromKey` 显示为与当前目录同名的 "test"。

## 修改内容

### 1. s3ObjectOps.ts — listDir 文件夹过滤（主修复）
在 CommonPrefixes 收集循环处增加过滤，仅接受合法的直接子目录前缀：
- 排除 `folder === prefix`（后端回显自身）
- 要求 `folder.startsWith(prefix)` 且 `folder.length > prefix.length`（防御异常前缀）

```ts
for (const folder of folders) {
  // 过滤后端回显的当前目录自身与不属于本层的异常前缀（OpenList/Alist 等代理会回显 prefix 自身导致目录自嵌套）
  if (folder === prefix || !folder.startsWith(prefix)) { continue }
  folderSet.add(folder)
}
```

此修复同时覆盖主列表（`useS3Entries.loadDir`）和移动/复制弹窗（`FmMoveCopyDialog.navigate`）两条调用链。

### 2. utils.ts — aggregateEntries 空段防护（次要加固）
在 `src/features/s3FileManager/utils.ts` 的 `aggregateEntries` 中，切分首段后若为空串（双斜杠异常键）则跳过，避免聚合出 `prefix + "/"` 的同名假文件夹：

```ts
} else {
  const seg = rest.slice(0, slashIdx)
  // 跳过双斜杠异常键（首段为空），避免聚合出与当前目录同名的假文件夹
  if (seg) { folderSet.add(`${prefix}${seg}/`) }
}
```

## 不改动的部分
- `useS3Entries.ts` L97 与 `FmMoveCopyDialog.vue` L162 的合并逻辑保持不变：上游 `listDir` 与 `aggregateEntries` 修复后，合并结果自然干净，无需重复过滤。
- L99 delimiter 失效探测条件保持不变：过滤掉回显项后，若后端确实忽略 delimiter，`listing.folders` 将正确为空，探测可正常触发。
