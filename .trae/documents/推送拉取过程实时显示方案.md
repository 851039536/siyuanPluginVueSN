# 推送/拉取过程实时显示方案

## 一、摘要

点击推送(含单平台/推送全部/强制推送)时,卡片输出面板当前**没有任何过程反馈**——运行期间仅操作栏按钮文字变为「推送中...」,输出面板显示的是**上一轮的旧结果**,直到本轮完成才一次性替换为新结果。

本方案在输出面板新增**轻量进度视图**:运行中逐平台显示「⟳ GitHub · 推送中...」实时状态行(复用既有 `pushProgress`/`pullProgress` 状态机,零底层改动),完成后自动切换为现有逐行结果输出。经用户确认:**轻量进度视图**(非实时 stdout 流式),且**推送+拉取同步覆盖**。

涉及 3 个代码文件 + 2 个 i18n 分片;不改 useRemoteProgress / GitExecutor / 注入契约。

## 二、现状分析

| 环节 | 现状 |
|------|------|
| 触发 | `CardActionBar` → `ops.pushSingle / pushToAll / handleForcePushToAll`(拉取同理 `pullSingle / pullToAll`) |
| 运行中状态 | `useRemoteProgress.remoteOpAll` 启动时把**全部已配置远程**置 `"pushing"`,完成置 `ok/fail`(3s 后清理);`remoteOpSingle` 仅置目标平台。状态经 `services.derived.getPushStatus(id, key)` / `isPulling(id, key?)` 已暴露给卡片层,**无需改注入契约** |
| 输出面板 | `OutputPanel.vue`(ProjectCard 底部两个实例,push/pull 各一)仅在 `pushOutputs/pullOutputs` 有条目时渲染;条目在操作**完成时一次性写入**——运行期间展示的是上一轮旧条目 |
| 进行中文案 | `i18n.pushing`("推送中...")已存在;**`pulling` 键不存在**,需新增 |
| 样式 | `.gp-console-line--ok/fail/skip/out/err` 定义于 `styles/index.scss:266-292`;`gp-spin` 为全局既有类(Shared.scss);OutputPanel 无自有 style 块,依赖面板全局样式链 |

## 三、改动方案

### 3.1 `components/ListView/OutputPanel.vue`

1. 新增可选 prop:

```ts
/** 运行中的平台实时状态(非空 = 操作进行中,渲染过程视图替代旧结果) */
runningStates?: { key: string, label: string }[]
```

2. 模板改为双分支:

```vue
<template>
  <!-- 过程视图:操作进行中,逐平台显示实时状态行(旧结果此时暂不展示,避免误导) -->
  <div
    v-if="runningStates?.length"
    class="gp-output"
  >
    <div class="gp-output-scroll">
      <div
        v-for="r in runningStates"
        :key="r.key"
        class="gp-console-line gp-console-line--run"
      >
        <Icon
          icon="mdi:loading"
          height="12"
          class="gp-spin"
        />
        <span>{{ r.label }} · {{ runningText }}</span>
      </div>
    </div>
  </div>
  <!-- 结果视图:操作完成后展示(现有逻辑不变) -->
  <div
    v-else-if="lines.length"
    class="gp-output"
  >
    ...(现有内容原样保留:控制台逐行 + AI 分析按钮 + 弹窗)
  </div>
</template>
```

3. 新增 computed:

```ts
/** 进行中文案:按操作类型取既有 i18n 键 */
const runningText = computed(() => (props.action === "push" ? props.i18n.pushing : props.i18n.pulling))
```

> 运行中不显示 AI 分析入口:结果视图整体隐藏,天然满足,无需额外判断。

### 3.2 `components/ListView/ProjectCard.vue`

新增两个 computed 并传入对应 OutputPanel(数据全部来自既有注入,零契约改动):

```ts
import { getProjectRemoteNames } from "../../utils"   // 已有该 utils 导出
import { PLATFORM_META } from "../../types"           // 取平台展示名(GitHub/Gitee...)

// 运行中的推送/拉取平台(useRemoteProgress 启动时显式置 "pushing",空闲默认 "pending" 不会误入)
const pushRunningStates = computed(() =>
  getProjectRemoteNames(project.value).flatMap(({ key }) => {
    if (services.derived.getPushStatus(project.value.id, key) !== "pushing") return []
    return [{ key, label: PLATFORM_META.find((pm) => pm.key === key)!.label }]
  }),
)
const pullRunningStates = computed(() =>
  getProjectRemoteNames(project.value).flatMap(({ key }) => {
    if (!services.derived.isPulling(project.value.id, key)) return []
    return [{ key, label: PLATFORM_META.find((pm) => pm.key === key)!.label }]
  }),
)
```

```vue
<OutputPanel
  :entries="pullOutputs"
  :running-states="pullRunningStates"
  ...原有 props 不变
/>
<OutputPanel
  :entries="pushOutputs"
  :running-states="pushRunningStates"
  ...原有 props 不变
/>
```

> 注意:ProjectCard 的 `project` 为 prop,访问器写法对齐该文件既有模式(若 project 非 ref 则去掉 `.value`,实施时按文件实际为准)。

### 3.4 i18n 分片(新增 `pulling` 键)

## 四、机制说明(为何零底层改动即可实时)

1. `remoteOpAll` 启动时同步把全部已配置远程置 `"pushing"` → 进度视图立刻出现全部平台行;`remoteOpSingle` 仅目标平台置位 → 单平台推送只显示该平台行
2. 完成瞬间状态转 `ok/fail` → 过滤条件 `=== "pushing"` 变空 → `v-else-if` 自动切回结果视图(此时新条目已写入),过渡无缝
3. 完成后 3s 的状态残留窗口内,结果视图已接管,不受影响
4. 强制推送(`forcePushToAll`)与拉取全平台走同一 `remoteOpAll`,自动获得过程显示

## 五、假设与决策

| 决策点 | 结论 | 依据 |
|--------|------|------|
| 实现方式 | 轻量进度视图,不做 stdout 流式 | 用户确认;流式需改 GitExecutor spawn 回调链,侵入大 |
| 覆盖范围 | 推送 + 拉取 | 用户确认;同一机制顺手接入,UI 口径统一 |
| 运行中旧输出处理 | 隐藏旧结果、仅显示过程行 | 旧结果会被本轮完成时覆盖,叠加展示易混淆新旧 |
| 过程行过滤条件 | 仅显示显式置位 `"pushing"` 的平台 | 空闲时 `getPushStatus` 默认返回 `"pending"`,不能作为运行判据 |
| i18n | 新增 `pulling` 键(中英分片),推送复用 `pushing` | 拉取侧无既有进行中键 |
| 图标 | `mdi:loading` + 既有 `gp-spin` | 与 WorkingTreePanel/审计按钮的加载态图标一致,零新增图标 |

## 六、验证步骤

1. `npx vue-tsc --noEmit` — 过滤改动文件零错误(既有无关错误忽略)
2. `pnpm i18n:verify` — 新键中英对齐
3. 用户执行 `pnpm lint`(AI 不运行)
4. 人工回归:
   - 推送全部 → 输出面板立即出现全部已配置远程的「⟳ xx · 推送中...」行,完成后切换为 [OK]/[FAIL]/[SKIP] 逐行结果
   - 单平台推送 → 仅该平台出现过程行
   - 强制推送 → 同推送全部
   - 拉取(全部/单平台) → 「拉取中...」过程行,完成后恢复结果视图
   - 空闲时输出面板维持原状(有旧结果显示旧结果,无则不渲染)
