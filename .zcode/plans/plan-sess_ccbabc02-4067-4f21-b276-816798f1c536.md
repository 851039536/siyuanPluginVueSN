# gitPush 新增「统计报告」页面（按指定项目统计）

在 gitPush 功能内新增一个 **统计报告** 视图（`PanelView` 增加 `"report"`），页内通过子 Tab 切换 4 个分区：**团队总览 / 代码贡献度 / 技术债务 / 代码热点**。全部数据**纯本地计算**（git 命令 + 确定性启发式公式），不调用 AI。

## 1. 页面切换（PanelHeader.vue）
- `types/meta.ts:192` — `PanelView` 联合类型增加 `"report"`
- `PanelHeader.vue` — 在 `.gp-view-toggle` 中仿照现有按钮新增一个视图按钮（图标 `mdi:chart-box`，`:title="i18n.reportView"`）
- `index.vue` — 新增 `v-if="currentView === 'report'"` 区块渲染 `CodeReportPanel`；在 `watch(currentView)` 中新增 `'report' → ensureReport()` 分支（懒加载）
- i18n 增加 `reportView`（统计报告 / Code Report）

## 2. 数据层（git 命令）
新增 `managers/ReportOps.ts`（GitExecutor 执行，GitPushManager 加私有协作器 + 公开委托方法）：
- `getNumstatLog(path, since?)` — 单条命令 `git log --since=<range> --pretty=format:%x1e%an%x1f%aI --numstat --no-renames`，一次取回全部所需数据（每提交：作者/ISO日期 + 每文件增删行）
- `getFirstCommitDate(path)` — `git log --reverse --format=%aI -1`（「全部」范围时计算实际分析时间范围标签，如 "5 months ago"）

由此可派生全部指标：作者提交数/代码行数(=新增行)/净增/平均提交大小/提交频率/影响文件数/活跃天数，文件修改次数/参与人数/最后修改时间。

## 3. 指标计算（确定性公式，`reportMetrics.ts`）
新增纯函数模块 `reportMetrics.ts`（feature 根，与 utils.ts 平级，避免 utils.ts 超行数上限）：
- **解析与聚合**：`parseNumstatBlocks(raw)`、`aggregateAuthorStats`、`aggregateFileStats`（单次遍历产出作者统计 + 文件统计两张表）
- **启发式公式**（示例反推，文档化）：
  - 作者质量分 `quality = clamp(60 + activeDays + 净增系数 + 一致性系数)`，等级分段 S≥90 / A≥80 / B≥60 / C≥40 / D，A级配 5★
  - 文件复杂度 `complexity = loc×0.45 + modCount×1.2`（LOC 用 `getNodeFsPathOs` 直接读文件行数，读不到显示「暂无数据」，与示例一致）
  - 文件稳定性 `stability = clamp(100 - modCount×3.5)`（示例 26次→7、24次→14、28次→0 反推吻合）
  - 技术债务等级：稳定性 ≤10→严重 / ≤30→高 / 其余→中；风险分 = 稳定性+复杂度加权
  - 热度 `heat = min(100, mods×2.2 + 参与人数×7 + 最近修改加分)`；分类 热点≥75 / 温热≥45 / 冷却≥25 / 冷门
  - 模板拼接「说明」文案（"此文件在过去6个月被修改了 X 次…"）、「优化建议」（按热点占比阈值输出）
- 每文件 LOC 仅对榜单 Top 文件用 fs 读取，控制开销

## 4. 类型与常量（`types/report.ts`）
新增 `types/report.ts` 并由 `types/index.ts` 转发导出：
- `ReportRange = "all" | "3m" | "6m" | "1y"`、`CodeReportData`、`AuthorReportRow`、`DebtFileRow`、`HotspotFileRow`、`HotspotLevelSummary`
- `GRADE_META` / `SEVERITY_META` / `HEAT_LEVEL_META` 元数据映射（labelKey + 颜色，驱动徽章/条形着色）

## 5. 状态与聚合（`composables/useCodeReport.ts`）
仿 `useCommitAnalysis.ts` 模式：选中项目 `projectId`、时间范围 `range`、`running`、聚合后的单对象 `reportData` computed、`runReport()`（跑 git 命令→`reportMetrics` 聚合）、`ensureReport()`（进入视图自动运行，项目已删则回退首个项目）。选择偏好持久化到 `GitPushStorage` 新增的 `reportPrefs`（`git-push-report-prefs`，`types/storage.ts`）。

## 6. UI（`components/report/`，5 个组件 + 对应 SCSS）
- `CodeReportPanel.vue` — 外壳：项目下拉（Select）+ 时间范围下拉（全部/近3月/近6月/近1年）+ 生成/刷新按钮 + 4 个子 Tab 栏 + loading/空/错误态
- `TeamOverviewSection.vue` — KPI 卡片（团队成员/总提交数/总代码量/平均质量/最活跃贡献者）+ 分析时间范围标签
- `AuthorContributionSection.vue` — 作者排行表（提交次数/代码行数/净增/平均提交大小/提交频率/影响文件数/质量评分[等级★]/活跃天数）
- `TechDebtSection.vue` — 按严重/高/中分组的文件债务表（路径/类型/评分/模板说明/修改次数/复杂度/代码行数/稳定性）
- `HotspotSection.vue` — 热点文件列表（热度徽章/修改次数/参与人数/最后修改/建议）+ 四类汇总表（数量/占比）+ 优化建议行

样式全部放 `styles/`（CodeReportPanel.scss 等 5 个文件），复用 `.gp-*` 共享类 + `gpr-` 前缀新类，遵循现有 Token 规范（`$font-size-2xs` 辅助文字、`$spacing-*`、`--b3-theme-*` 变量、`.vp-btn` 按钮），SCSS 不写 `box-shadow`。
