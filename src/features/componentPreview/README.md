# 组件预览（Component Preview）

在思源内以独立窗口/页签形态查看共享 Codex UI 组件库（`src/components/`）全部 42 个组件的真实渲染用法快照，附可复制的示例代码，便于组件开发者查看效果、改动后快速回归验证。

## 功能

- **双形态承载（纯官方 API）**：`plugin.addTab` 注册自定义 Tab 模型 + `openTab({custom})` 在主窗口创建页签；面板头部「在独立窗口打开」调 `openWindow({tab})` 把页签移入浮动窗口；浮动窗口内经 `isFloating`（`getFrontend() === "desktop-window"`）隐藏重复面板标题与打开按钮。
- **全组件覆盖**：Avatar / Badge / Button / Card / Chart / Checkbox / ColorField / ConfirmDialog / **ConfirmPopup** / DatePicker / **Dialog** / Divider / **Drawer** / FormField / **FileUpload** / IconWrapper / Input / InputGroup / Label / Listbox / Loader / Paginator / Panel / RadioButton / Select / Slider / SpeedDial / Splitter（与配套的 SplitterPanel 共用「Splitter」一个分区） / Switch / Tag / Textarea / **Timeline** / **Tabs**（与配套的 `TabList` / `Tab` / `TabPanels` / `TabPanel` 共用「Tabs」一个分区） / **Toolbar** / ToggleButton / **Tooltip** 各一个分组分区（`InputGroup` 与 `InputGroupAddon` 为配套组件，共用「InputGroup」一个分区），分组内为典型 props 组合（含具名/作用域插槽）快照卡片。
- **示例清单驱动**：预览数据集中在 `previewData/`（一份清单），渲染层通用遍历——新增组件/新用法只需在清单追加，不改渲染框架。清单里的 `code` 模板与渲染 props 共用同一数据源，杜绝漂移。
- **受控示例可交互**：声明了 `modelValue` 的组件（Slider / Input / Select / Switch / Checkbox / RadioButton / DatePicker / Listbox 等）在卡片内即可直接拖动、输入、点选，状态由 `PreviewStage` 持有的本地值回写 —— 所以 `showValue` 的数字、开关的选中态等会实时变化。**仅当目标组件确实声明了该 prop 时才注入**（否则 `modelValue` / `onUpdate:modelValue` 会落进 attrs，多根组件如 `FormField` 会因此报 extraneous attrs 警告）；切换全局尺寸档位只重新解析注入的 `size`，**不会覆盖你已经改动的本地值**。`render` 复合示例内部的子组件仍使用静态 props（示例 `code` 里展示的仍是最初的静态组合）。
- **复合控件内嵌能力**：`Input` 的 `borderless` 去边框去底色（三条高特异性选择器覆盖基类 hover/focus-within），供「标签输入框」这类自定义容器把输入框内嵌其中；焦点反馈由外层容器的 `:focus-within` 承担。
- **多行文本域**：`Textarea` 是新增的**独立多行控件**（与 PrimeVue `Textarea` 语义对齐），四档尺寸 + `label`/`required`/`hint`/`error`/字数统计齐备，三项特有开关：`autoResize`（内容增多自动增高，`rows` 为初始高度与默认下限、`minRows`/`maxRows` 可覆盖；`maxRows` 不传则不设上限，超出上限时转内部滚动）、`variant`（`outlined` 默认 / `filled` 实底，实底聚焦用内嵌 outline 环，因实底 border 为透明）、`fluid`（**默认 `true`** 占满容器宽；`:fluid="false"` 时交回原生 `cols` 决定固有宽度）。⚠️ 本组件**无插槽**；`Input` 的 `type="textarea"` 为兼容保留的旧入口，**新代码一律用 `Textarea`**。
- **按钮式开关**：`ToggleButton` 是**单按钮布尔开关**（`v-model` 为 boolean），参考 PrimeVue ToggleButton。**内部复用共享 `Button`（零样式复制）**：未按下走 `variant="ghost"` + `outlined` 取中性描边（`error` 时改用 `severity="danger"` 的红描边），按下走 `severity="primary"` 的填充外观 —— 因此**强弱对比明显，与分段组（弱对比文字色切换）观感有意区分**。`onLabel`/`offLabel`/`onIcon`/`offIcon` 按状态切换，**均无默认值**（项目禁止硬编码 UI 文案；都不传时会渲染空内容并在 DEV 告警）；无文案时按钮自动退化为**方形纯图标按钮**（沿用 `Button` 的 icon-only 档位尺寸，避免 `gap` 造成图标偏心）。⚠️ 无障碍红线：**可见文案/图标随状态变化时，必须提供不随状态变化的 `ariaLabel` / `ariaLabelledby` / `title`**（PrimeVue 官方建议，Dev 环境会对缺失场景告警）。⚠️ 选用边界：**单按钮开关用 `ToggleButton`；一组互斥选项的分段切换仍用 `Button` 分组 + `:aria-pressed`**（后者是本项目已有范式，未迁移）。`fluid` 默认 `false`（按钮天然内容宽，与 `Textarea.fluid` 默认 `true` 相反）。
- **浮动动作按钮**：`SpeedDial` 是**主按钮按下后按方向与轨迹展开一组动作**的浮钮（参考 PrimeVue SpeedDial）。**内部复用共享 `Button`（零样式复制）**：主按钮与动作项都是 `rounded` 的圆形浮钮，外观/悬停/焦点环/禁用态全部沿用库内既有约定。8 个 `direction` × 四档 `type`（`linear` / `circle` / `semi-circle` / `quarter-circle` + `radius`，扇区中心始终对准所选方向）；轨迹偏移由私有纯函数 `speedDial/geometry.ts` 一次性算出（`O(n)`）。`position` 四档角落 + `offset`，**默认 `position: fixed`**（需在舞台沙箱覆盖为 `absolute`，见上节）。动作气泡复用**思源内置 `b3-tooltips b3-tooltips__{方向}` + `aria-label`**（无新依赖）；展开时主按钮图标旋转 45°（提供 `hideIcon` 时改用独立图标、不旋转）。无障碍按官方约定落实：`aria-haspopup` / `aria-expanded` / `aria-controls`、列表 `role="menu"`、动作项 `role="menuitem"`，键盘 Enter/Space 切换、方向键与 Home/End 移动焦点、**Esc 关闭并把焦点返还主按钮**（鼠标操作不抢焦点）。`hideOnClickOutside` 默认开启；**不做 `mask`**。尺寸用 `size`（同时决定轨迹几何的按钮边长），**请勿经 `buttonProps.size` 覆盖**，否则几何与渲染会脱节。⚠️ 本组件示例的 `visible` 默认给 `true`，便于目视展开形态。
- **分页器**：`Paginator` 由 **`page`（1 基）/ `rows` / `total`** 三要素驱动（对齐项目既有「当前页 / 总页数」心智，**不采用** PrimeVue 的 `first` 零基行偏移）。组成全部用**显式 props** 控制（`showFirstLast` / `showPageLinks` / `pageLinkSize` / `showReport` / `rowsPerPageOptions` / `showJumpInput` / `alwaysShow`），**不采用** PrimeVue v5 的 `template` 字符串。页码窗口以当前页为中心滑动、首页与末页恒显，且**窗口与首末页只隔 1 页时直接补上该页、间隔 ≥2 页才折叠为省略号**（避免「跳号却看不到省略号」的错觉）。默认 `reportTemplate` 为 `"{page} / {totalPages}"`，可精确复现项目原有「1 / 3」文案；占位符支持 `{page}` / `{totalPages}` / `{rows}` / `{total}` / `{first}` / `{last}`，未识别的占位符原样保留。`rowsPerPageOptions` 接受 **`Array<number | SelectOption>`** —— 传对象即可携带本地化文案（如「30 张/页」），传数字则 label 取数字本身。边界兜底：`rows <= 0` 视为 1（否则 `Math.ceil(total / 0)` 得 `Infinity`）、`total <= 0` 视为 0、**页码越界（含数据变少后超界）自动收敛并回派 `update:page`**、`rows` 变更自动回第 1 页。导航按钮的 aria-label 由 `labels` 提供（中文默认值 + 可覆盖为调用方 i18n 文案），故**零 i18n 分片改动**。⚠️ 组件以 `v-model:page` 驱动，而预览框架只识别 `modelValue` ⇒ **示例为静态快照，点击页码不会改变高亮**（故示例特意用不同 `page` 值覆盖贴左 / 居中 / 贴右 / 折叠等形态）。
- **时间线**：`Timeline` 把一串按先后发生的事件沿线排布，由 **`value`**（事件集合，元素为任意对象）+ **`layout`** 两向（`vertical` 默认：事件自上而下、线在左/右；`horizontal`：事件自左向右、线在上/下）+ **`align`** 三档（竖向 `left` 默认 / `right` 镜像 / `alternate` 左右交替；横向 `top` 默认 / `bottom` 镜像 / `alternate` 上下交替）驱动，渲染完全交给 **`content`（必填）/ `opposite`（对侧内容，如时间戳）/ `marker`（节点，缺省为主题色空心圆）** 三个作用域插槽（作用域统一 `{ item, index }`；官方另有 `icon` 作用域参数与 `connector` 插槽，本项目**均不提供** —— 图标由调用方在插槽内自行渲染 `IconWrapper`）。`opposite` 容器**恒渲染**（即使未传该插槽），以保持两侧等宽、竖线位置稳定；`alternate` 下 0 基偶数索引内容在右、奇数索引在左（等价官方 `nth-child(even) { flex-direction: row-reverse }`），对侧文本始终朝线一侧对齐（横向布局下两侧都是横排文本块，改为统一左对齐），内容一律左对齐。**横向布局**下各列等高（列高由该列内容决定），对侧与内容各占列高的一半 ⇒ 分隔行落在垂直中线上、节点跨列对齐，连接线为横线且同样**末列不延长**；⚠️ 若各列 `opposite` 的高度不一致（例如换行后行数不同），连线会呈阶梯状（与官方实现一致）—— 需要严格水平对齐时让 `opposite` 等高或留空。默认节点是 **10px 空心圆**（2px 主题色描边 + 背景色填充，填充遮住穿行的线），连接线 2px 取 `--b3-border-color`，**末项不再延长**（列表自然收口）。四档 `size` **只驱动字号**（10/12/14/16px），节点直径与线宽恒定，切换档位时线条结构不抖动。**纯展示**：无自有事件、无 hover / 焦点 / 过渡样式，组件内无可聚焦元素（Tab 直接跳过整块），根节点为语义化 `<ol>`、每项为 `<li>`（额外 attrs 透传到 `<ol>`）；节点上的点击行为由调用方在自己的插槽内容里提供。⚠️ 本分区的示例由清单的 **`slots`** 字段渲染（见「具名插槽」与「清单扩展指南」）。
- **标签页**：`Tabs` 五件套（`Tabs` / `TabList` / `Tab` / `TabPanels` / `TabPanel`，参考 PrimeVue Tabs）—— `Tab` 与 `TabPanel` 靠**同一个 `value` 配对**，`TabList` 与 `TabPanels` 分列两侧。`value` **传入即受控**（配 `v-model:value`），**不传时组件内部自持**（非受控，官方同款语义）⇒ 本分区示例统一传一个初始 `value`（首屏即有激活项），预览框架不接管 `value`，**点击切换真实可交互**。`update:value` **幂等**（仅值实际变化时派发）。⚠️ **`lazy` 双开关**：开启后未激活面板**完全不进 DOM**（切走再回来会**重置面板内状态**，示例中放输入框可直观看到）；默认关闭时所有面板只被 `display: none` 隐藏、**状态保留**。**无障碍**（严格对齐官方）：标签栏 `role="tablist"` + `aria-orientation`，每个标签 `role="tab"` + `aria-selected` + `aria-controls` + `id`，面板 `role="tabpanel"` + `aria-labelledby` 指回标签；**roving tabindex**——仅激活标签可被 Tab 键停留（`tabindex` prop 为基准值、其余 `-1`，面板共用同一值，传 `-1` 可把整组移出 Tab 序列）；键盘 ←/→ 移焦点并回绕、Home/End 跳首末、PageUp/PageDown **仅滚动不聚焦**、Enter/空格选中（焦点移动走 `focus()` + `scrollIntoView({ block: "nearest" })`）。标签栏**横向溢出时可滚动（滚动条隐藏）**，并有 `scrollStrategy`（`nearest` 默认 / `center` / `false` / 自定义函数）把激活标签**自动滚入视野**。⚠️ **与官方有意差异**：①不做滚动导航按钮与 `previcon` / `nexticon`；②不做 v5 已废弃的 `scrollable`；③不做 `as` / `asChild` 多态渲染与 `dt` / `pt`；④活动指示器为**静态下划线**（激活标签自身 `::after` 2px 主色），官方那套「测量 + `ResizeObserver` + 150ms 定时器」的**滑动墨条不做**（面板宽度频繁变化时墨条易错位抖动）；⑤激活判定用**严格相等**（官方 `equals()` 深比较是为支持任意类型）。⚠️ 公开组件无内置文案（`TabList` 的组名由 `ariaLabel` / `ariaLabelledby` 提供）；本分区示例由清单的 **`render`** 字段组装子树（`render` 返回值是 `Tabs` 的**子节点**，不是 `Tabs` 本身）。
- **工具栏**：`Toolbar` 是**三段式横向布局容器**（参考 PrimeVue Toolbar）：`start`（左）/ `center`（居中）/ `end`（右）三个插槽，**均无作用域参数**，且**三个容器恒定渲染**（官方产物里没有 `v-if`、没有 fallback ⇒ 未传某段时该 `div` 仍在，位置不随内容增删跳动）。**纯布局：无自有事件、无自有状态、无 hover/过渡样式**，内容交互由内部共享控件承担；无障碍靠根元素 `role="toolbar"` + `ariaLabel` / `ariaLabelledby`（组件无内置文案）。**`center` 精确居中**：两端容器各 `flex: 1 1 0` 配平（官方为 `justify-content: space-between`，三段俱全时 center 只能大致居中，属有意改进），并给各段 `min-width: 0` 避免长内容把 center 挤出去。**本项目扩展**（官方只有 `ariaLabelledby` 一个业务 prop）：`variant`（`outlined` 默认 = surface 底 + 1px `--b3-border-color` + 6px 圆角 / `filled` 实底无边框 / `borderless` 无边框无底色）、`padded`（默认 `true`；关闭后四向贴合但**仍保留档位最小高度**，高度不随内容随机变化）、`wrap`（默认 `false`；开启后 `start` 独占首行，`center` 贴左、`end` 贴右落在次行）、四档 `size`（字号 10/12/14/16，驱动内边距 / 最小高度 / 段间距；**边框 1px 与圆角 6px 恒定**，切档不抖动）。⚠️ **档位传不进插槽**（Vue 无法向插槽注入 props）⇒ 调用方需把同档 `size` 同时传给内部共享控件，否则容器与控件高度会脱节；本分区示例通过 `slots` 工厂的第二参取注入后的 `size` 来对齐（见「清单扩展指南」）。不引入官方 `dt` / `pt` / `ptOptions` / `unstyled`，且用默认 attrs 透传（官方为 `inheritAttrs: false` + PT）。
- **对话框**：`Dialog` 是**通用模态容器**（参考 PrimeVue Dialog）—— `header`（标题）+ 默认插槽（内容区）+ `footer`（页脚，文本或插槽存在才渲染）三段结构；`showHeader` 关掉标题栏（**连带关掉关闭按钮**）、`closable` 只关关闭按钮；**九档 `position`**（`center` 默认 / 四边 / 四角，模板类驱动、零 JS 定位）；**四档 `size`** 驱动弹窗宽度 320/400/520/680px、内边距与基准字号 10/12/14/16（`max-height: 80vh`、1px 描边与圆角 `$r-base` **恒定**，**不用阴影**——层级靠遮罩对比）。`visible` **受控**（`v-model:visible`），关闭请求一律回派 `false`；关闭路径 = 关闭按钮 / Esc（`closeOnEscape` 默认开）/ 遮罩点关（`dismissableMask` **默认 `false`，与官方一致**，且**需在遮罩上按下并抬起**才算数，弹层内按下、遮罩上抬起不误关）/ 插槽内自建按钮。⚠️ `modal` **默认 `true`**（官方默认 `false`，属**有意差异**：本项目遮罩恒定渲染，非模态时加 `--plain` 让遮罩透明且 `pointer-events: none`，页面其余部分仍可交互，点关随之失效）。**焦点**：打开时优先聚焦容器内 `[autofocus]`（footer → header → content 顺序）、否则聚焦容器，关闭时归还打开前元素；`aria-labelledby` 指向标题元素（`showHeader` 且有标题文本或 `header` 插槽时），否则回退 `ariaLabel`。⚠️ **与官方有意差异**：不做 `draggable`（官方默认开）/ `maximizable` / `breakpoints` / `appendTo`（**不 Teleport，就地 fixed**）/ `blockScroll` / ZIndex 管理与 `dt` / `pt` / `ptOptions` / `unstyled`，`container` 插槽亦无官方 `maximizeCallback` / `initDragCallback`。⚠️ 遮罩点关 / Esc / 焦点接管与归还由私有目录 `overlay/`（`useOverlay`）提供，与 `ConfirmDialog` 共用（该外壳也把确认框的点关判定升级为同一套官方语义）。本分区示例为**打开态静态快照**（`visible` 由调用方持有，而预览框架只接管 `modelValue`），`code` 展示真实 `v-model:visible` 用法；页脚 / 内容里的共享控件经 `slots` 工厂第二参取同档 `size`。
- **抽屉**：`Drawer` 是 `Dialog` 的**「贴边 + 轴向滑入」姊妹组件**（参考 PrimeVue Drawer）—— 结构完全相同（`header` + 默认插槽内容区 + `footer`，文本或插槽存在才渲染页脚），区别只在外壳：`Dialog` 是居中/九档定位 + fade + `scale(0.98)`，`Drawer` 是**四向贴边 + 沿贴合边轴向滑入**（`left` 默认 / `right` / `top` / `bottom`，模板类驱动、零 JS 定位；过渡同为 `0.12s ease`，**不叠加缩放**）。**四档 `size`** 驱动**贴合边方向上的延伸量** 320/400/520/680px（`left` / `right` 落在宽度、`top` / `bottom` 落在高度，沿边方向恒 `100%` 铺满）+ 内边距 + 基准字号 10/12/14/16；⚠️ 这是对官方（无 `size` prop）的**本项目扩展**，台阶与 `Dialog` 宽度一致（同一套档位心智）。**视觉**：贴死视口边缘的一侧**不画描边**、圆角只在朝内一侧出现（Codex 边框优先、**不用阴影**），层级靠遮罩对比区分。**关闭路径与焦点行为与 `Dialog` 逐一对应**：关闭按钮 / Esc（`closeOnEscape` 默认开）/ 遮罩点关（`dismissableMask` **默认 `false`**，同样**需在遮罩上按下并抬起**）/ 插槽内自建按钮；打开时优先聚焦容器内 `[autofocus]`（footer → header → content）、否则聚焦容器，关闭时归还打开前元素；`aria-labelledby` 指向标题元素，否则回退 `ariaLabel`。⚠️ `modal` **默认 `true`**（与官方 Drawer 一致），非模态时遮罩透明且 `pointer-events: none`（**与 `Dialog` 同一套 `--plain` 范式**，页面其余部分仍可交互，点关随之失效）。**命名统一（与官方有意差异）**：官方 `dismissable` → 本项目 `dismissableMask`、官方 `showCloseIcon` → 本项目 `closable`，与库内 `Dialog` / `ConfirmDialog` 同名同义（同类语义全库只有一个名字，优先于字面对齐官方）。**与官方其它有意差异**：不做 `full` 位置档（全屏浮层由 `Dialog` 的九档位置承担，避免两套全屏入口）/ `blockScroll` / `closeButtonProps`（`object` 型 props 袋，同 `Panel` 拒绝 `toggleButtonProps` 的判据，改由 `closebutton` 插槽覆盖）/ `closeIcon`（改由 `closeicon` 插槽覆盖，与 `Dialog` 一致）/ `baseZIndex` / `autoZIndex`（遮罩统一 `z-index: 10000`）与 `dt` / `pt` / `ptOptions` / `unstyled`。**事件**只做 `update:visible` / `show` / `hide` / `after-hide`，**与 `Dialog` 事件集完全一致**（不做官方 `before-hide` / `after-show`，二者在过渡钩子里分别与 `hide` / `show` 时机重合）。⚠️ 遮罩 / 点关判定 / Esc / 焦点接管与归还**全部复用私有目录 `overlay/`**（`useOverlay` 与 `Dialog` 同一套，零复制粘贴）。本分区示例为**打开态静态快照**（口径同 `Dialog`），`code` 展示真实 `v-model:visible` 用法。
- **文字提示**：`Tooltip` 是**锚点旁的小气泡**（参考 PrimeVue Tooltip）。⚠️ **官方形态是指令**（`v-tooltip`），本项目按仓库硬规则（`src/components/` 是唯一 UI 出口、组件须能进预览面板与清单）做成**组件**：`<Tooltip text="…" :target="() => anchor" />`，方位由 `placement` prop 表达而非官方修饰符（`v-tooltip.top`）。**开合双模式**：`visible` **传入即受控**（配 `v-model:visible`）、**不传即自持**（非受控，与 `Panel.collapsed` 同一范式）——非受控时由 `trigger` 驱动，`both`（默认）/ `hover` / `focus`，⚠️ **focus 默认开启**是刻意选择：键盘用户必须能触发气泡，否则提示信息对其不可达。`showDelay` / `hideDelay` 默认 0（对齐官方），密集图标按钮可设延迟避免扫过时乱闪。**定位**：`position: fixed` + 视口坐标（**不 Teleport**，与 `ConfirmPopup` 同一范式），四向 `placement`（`top` 默认）+ **`auto`**（**优先上方**、放不下下翻、两侧都不够取空间更大的一侧；⚠️ 偏好与 `ConfirmPopup` 的「优先下方」**相反**，因官方 Tooltip 默认方位是 top），显式方位**只做视口 8px 钳制、不翻转**，带 8px 指向三角；`window` 的 `scroll`（`capture: true`）与 `resize` 触发 **rAF 节流**重算。**几何计算复用 `confirm/position.ts`**（`resolvePopupPosition`：主轴定位 / 交叉轴对齐 / 视口钳制 / 三角偏移，零复制粘贴），tooltip 侧只补「auto 偏上方」一处差异。**非模态、无遮罩、不可交互**：气泡 `pointer-events: none`（**关键**——否则气泡盖住锚点会触发 `pointerleave`，造成显示/隐藏抖动）。`maxWidth` 默认 240，超长文案在气泡内换行而非拉成长条。四档 `size` **只驱动字号 10/12/14/16 与内边距**（气泡宽度随内容自适应）。⚠️ 锚点晚于组件挂载出现时用**有界轮询**（每 200ms、上限 15 次）补挂监听。锚点监听、延迟定时器与该轮询集中在私有组合式函数 `tooltip/useTooltipTrigger.ts`（组件只做定位测量与模板编排）。私有目录 `tooltip/`（types / position / useTooltipTrigger，禁止 feature 直接导入）；**与官方有意差异**：不做 `escape` / `fitContent` / `autoHide`（气泡不可交互，此三者无意义）/ `id` / `class`（走默认 attrs 透传）/ `dt` / `pt` / `ptOptions` / `unstyled`。本分区示例由 `previewData/tooltip.ts` 内联的**演示宿主**驱动（包裹按钮作锚点 + 气泡），默认非受控 ⇒ **hover / focus 在预览中真实可用**；方位与尺寸对比示例用宿主专用的 `pinned` 脚手架开关强制常显（hover 触发在静态快照中不可见）。
- **文件上传**：`FileUpload` 是**拖拽 + 点选 + 队列管理 + 校验 + 进度**的上传控件（参考 PrimeVue FileUpload）。**两种模式**：`advanced`（默认，虚线拖拽区 + 文件列表 + 底部上传 / 取消操作栏）/ `basic`（仅一个选择按钮 + 已选数量 `Badge`，适合嵌进工具栏）。**队列为非受控自持**（组件持有 `File[]`，经 `select` / `remove` / `clear` 对外通报）——与官方一致，调用方无需接管每次增删。**选择与拖拽走同一条入库路径**（`addFiles` 是唯一入口），故校验、去重语义、事件在两处完全一致。**校验内置**：`accept` 支持 `.pdf`（扩展名）/ `image/*`（主类型通配）/ `image/png`（完整 MIME）三种形态混用（⚠️ 浏览器下 `File.type` 可能为空，此时**回退扩展名匹配**，避免把合法文件一律拒掉）；`maxFileSize`（字节）与 `fileLimit`（数量）超限时**只拒绝不合格项、其余照常加入**——数量上限按「已有 + 本次」累计判断，故一次拖入过多文件时「能加的先加上」，而不是一票否决整批。失败项走**双通道**：`invalid` 事件（载荷含 `reason` 分类与已插值文案）+ 行内红色提示列表（`role="alert"`）。文案全部可覆盖 ⇒ 零 i18n 分片改动。⚠️ **组件不做任何网络请求**：`upload` 事件只把队列交给调用方，`uploading` 与 `progress` 由调用方按自身上传通道回报（进度条**传入 `progress` 才渲染**，0 也会显示以便「已开始」可见）。**其它要点**：拖拽高亮用 `relatedTarget` 判定真实离开（子元素间移动也会冒泡 `dragleave`，只看事件本身会反复闪烁）；拖拽区可键盘操作（`role="button"` + Enter/Space）；图片缩略图用 `URL.createObjectURL`，**队列变化与组件卸载时显式 `revokeObjectURL`**（否则长会话持续泄漏）；**列表行按「紧凑单行」设计** —— 行高由缩略图决定（`previewWidth` **默认 24**，比官方 50 紧凑得多；占位尺寸与图片实际边长由 `--si-fu-thumb` 单一变量驱动），文件名与大小**上下堆叠**（并排会撑宽行并挤占文件名空间），行纵向内边距 2px、行间距 2px，且**移除按钮按档位收紧为 20/22/24/26px** —— 共享 `Button` 的 icon-only 档位是 22/28/36/44px，**它会反过来成为行高的下限**（比缩略图还高），故必须覆写（覆写规则抬到 `(0,3,0)` 以稳压 Button 的 `(0,2,0)` 同特异性规则）；⚠️ **左侧标识位不画框、不铺底**（行本身已有描边，若再套一层描边 + 底色的方块，非图片文件会呈「框里套框」的双层边框、整体偏重），仅真实图片保留圆角；且**图标尺寸与 `previewWidth` 刻意解耦** —— `previewWidth` 是「图片缩略图的展示尺寸」，而非图片的文件图标是**文字性的行内标识**，应与行文字同阶（按档位字号 +2px 取 12/14/16/18），否则默认档位会出现「18px 图标配 12px 文件名」的头重脚轻；同时**左列占位宽按内容分别取 `--si-fu-thumb`（图片）或 `--si-fu-thumb-icon`（图标）**，避免图标右侧留出无用空档；**列表高度按档位设限**（132/168/200/240px，约 5~6 行）；`defineExpose` 暴露 `choose()` / `clear()` / `upload()`（对齐官方方法名）。私有目录 `fileUpload/`（types / validate / **ChooseArea** / **FileList**，禁止 feature 直接导入；后两者为私有子部件、不计入公开清单，拆出后父组件保持在 500 行硬阈值内）。**与官方有意差异**：不做 `url` / `withCredentials` / `auto` / `customUpload` / `before-upload` / `before-send` / `error` / `uploader` 与进度事件（**不做网络请求**，全部交由调用方）；不做上传后文件区（`uploadedFiles` 恒空，仅为对齐官方插槽作用域形状而保留 `removeUploadedFileCallback`）；不做 `chooseButtonProps` / `uploadButtonProps` / `cancelButtonProps` 对象袋（同 `Panel` 拒绝 `toggleButtonProps` 的判据，改由图标插槽 + 文案 props 覆盖）；不做 `style` / `class`（走默认 attrs 透传）与 `dt` / `pt` / `ptOptions` / `unstyled`。⚠️ 本分区示例由 `previewData/fileUpload.ts` 内联的**演示宿主**驱动 —— 它装载时用 `new File([...])` 造**纯内存假文件**并经原生 input 的 `DataTransfer` 预置进队列（**不发起请求、不落盘**），使快照能直接呈现列表 / 缩略图 / 错误态；宿主本身也可真实交互（选择、拖拽、移除、清空均可用）。
- **确认对话框**：`ConfirmDialog` 受控显示（`v-model:visible`），**命名对齐官方 `ConfirmationOptions`**（`header` / `message` / `icon` / `acceptLabel` / `rejectLabel`），但**驱动方式改为受控** —— 官方靠 `useConfirm().require()` 命令式服务（`visible` / `target` / `position` / `acceptProps` 全在 `ConfirmationOptions`），而本项目组件库刻意零 plugin / 零全局服务。`acceptSeverity`（`danger` 默认 / `primary`）取代官方 `acceptProps.severity` 对象袋（与 Panel 拒绝 `toggleButtonProps` 同一判据）；`acceptLoading` 为异步确认提供按钮加载态。**九档 `position`**（`center` 默认 / 四边 / 四角）为模板类驱动、零 JS 定位（九档位置类型与遮罩基础样式由私有目录 `overlay/` 提供，与 `Dialog` 共用）；`closable` **默认 `false`**（官方 Dialog 默认 `true`，但确认框已有「取消」，属有意差异）；`dismissableMask`（遮罩点关，沿用官方 Dialog 命名）与 `closeOnEscape` 可分别关闭 —— 点关判定已升级为官方「在遮罩上按下并抬起」语义（弹层内按下、遮罩上抬起不误关）。⚠️ 官方**没有 `header` / `footer` 插槽**（那只是 PT 段落名），可用插槽只有五个：`message`（作用域 `{ message, icon }`，官方给 `ConfirmationOptions` 对象属有意差异）/ `icon`（`{ class }`）/ `accepticon` / `rejecticon` / `container`（整块替换，作用域含 `header` / `message` / `icon` / `acceptLabel` / `rejectLabel` 与 `closeCallback` / `rejectCallback` / `acceptCallback`；**不提供官方 `initDragCallback`**，因不做 `draggable`），另有**默认插槽**覆盖消息区（优先级：默认插槽 > `message` 插槽 > `message` prop）。无障碍：`role="dialog"` + `aria-modal` + `aria-labelledby` 自动指向标题，打开时聚焦容器（**刻意不聚焦确认按钮**，避免危险操作被 Enter 误触）、关闭归还焦点。
- **气泡确认**：`ConfirmPopup` 与对话框**共用同一套内容段与插槽**，区别只在外壳 —— 它贴 `target` 锚点弹出（`HTMLElement | () => HTMLElement | null`，通常传触发按钮的包裹元素），**非模态、无遮罩**，点组件与锚点之外或按 Esc 关闭（`dismissable` / `closeOnEscape` 可分别关闭）。定位为 `position: fixed` + 视口坐标（**不 Teleport**，与 Select / DatePicker 的相对定位范式一致），`placement` 支持 `auto`（默认：优先下方、放不下上翻、水平居中）与八个显式方位（显式方位**只做视口 8px 钳制、不翻转**），并带 8px 指向三角；`window` 的 `scroll`（`capture: true`，任意滚动容器）与 `resize` 会触发**rAF 节流**重算，气泡跟随锚点。⚠️ 无 `closable`（气泡靠点外部 / Esc 关闭）；`target` 取不到时退化为视口居中，不会渲染到左上角。本分区示例由 `previewData/confirmPopup.ts` 内联的**演示宿主**驱动（按钮 + 气泡 + 自持开合），因为「锚点元素 + 开合状态」无法用纯清单数据表达。
- **分隔线**：`Divider` 用 **`type`**（`solid` 默认 / `dashed` / `dotted`）× **`layout`**（`horizontal` 默认 / `vertical`）× **`align`** 描述一条 1px 细线，默认插槽可在线上承载文字或图标（**仅有默认插槽**，无具名/作用域插槽）。`align` 语义严格对齐官方：水平取 `left` / `center` / `right`、垂直取 `top` / `center` / `bottom`；**未传时按居中处理**，且**取值与方向不匹配（如水平 + `top`）时不报错、静默回落居中**。实现上**用两段真实线段 + 中间内容**，按对齐隐藏**首段**（`left` / `top`）或**末段**（`right` / `bottom`）线 —— **不复刻官方「根元素画线 + 内容背景遮罩」**：遮罩底色必须等于父容器底色，而本项目父容器底色有 `--b3-theme-background` / `--b3-theme-surface` / Card 内部等多种，遮罩必露色块。线色取 `--b3-border-color`（相邻色陷阱：surface 与 background 灰度仅差约 3%，画细线不可辨）；默认间距水平 `$s-3 0` / 垂直 `0 $s-3`（官方主题为 `1rem`，属有意差异化；单根元素 ⇒ 调用方可用 `class` / `style` 直接覆盖）。⚠️ **垂直分隔需要父容器有确定高度**（非 flex 父容器下会塌成 0），组件已用 `min-height` 兜底；本分区的垂直示例用 `style="height: 80px"` 透传高度。**纯展示**：无自有事件、无 hover / 焦点样式、组件内无可聚焦元素。
- **分割面板**：`Splitter` + 配套的 **`SplitterPanel`**（两个公开组件共用本分区，API 与官方同形）把容器按百分比切成可拖动调整的多栏：`layout`（`horizontal` 默认 / `vertical`）、`gutterSize`（分隔条 px，默认 4，同时决定拖拽命中区）、`step`（方向键步进百分比，默认 5）、`disabled`、`sizes`（**传入即受控**，配合 `v-model:sizes`）、`stateKey` + `stateStorage`（持久化到 session / localStorage，**受控时不读写**）、`resizeLabel`（分隔条无障碍名称，中文默认值 ⇒ 零 i18n 改动）；`SplitterPanel` 提供 `size`（初始百分比，未指定者与其它未指定者均分剩余）、`minSize` / `maxSize`（夹取范围，两侧之和恒定）、`collapsible` + `collapsedSize`（拖到 `minSize` 以下**吸附折叠**）。**结构**：分隔条渲染在**面板内侧**（首个面板没有），因此拖动分隔条调整的是「它所属面板 + 前一个面板」，实现上无需对默认插槽做子节点手术，`v-for` / `v-if` 面板都能正常工作。**无障碍**：分隔条 `role="separator"` + `aria-orientation`（取分隔条**自身的物理方向**：水平布局下是竖条）+ `aria-valuenow/min/max`（左侧面板的尺寸与其约束）+ `tabindex`（`disabled` 时移除），Tab 聚焦后用 ←→（垂直布局用 ↑↓）按 `step` 调整，聚焦 / 悬停 / 拖拽时细线变主题色（以该色变作为可见焦点指示，故不加 outline）。⚠️ 两点注意：①**垂直布局与嵌套布局都需要父容器有确定高度**（本分区示例用 `style="height: …"` 透传），否则百分比基础尺寸无处解析；②`stateKey` 的读写包了 try/catch（隐私模式 / 超配额时不至于抛错），存储在 **Web Storage** 而非插件数据 —— 组件库刻意不引入 `@/utils/pluginStorage`，需要落进插件数据时请监听 `resizeend` 自行保存；③拖拽走 Pointer Events + `setPointerCapture`（指针移出分隔条仍持续调整），`touch-action: none` 保证触屏拖拽不被页面滚动接管。
- **面板**：`Panel` 是可折叠的内容容器（参考 PrimeVue Panel），由 **`header`**（头部文本，或用 `header` 插槽整体替换）+ **`toggleable`**（是否可折叠，默认 `false`）+ **`collapsed`** 驱动，插槽共 6 个（`default` / `header` / `icons` / `togglebutton` / `toggleicon` / `footer`），事件为 `update:collapsed`（新值）与 `toggle`（`{ originalEvent, value }`）。**`collapsed` 不传时组件内部自持**（非受控，可独立开合），传入即受控（配合 `v-model:collapsed`）—— 因此本分区的「可折叠」示例在预览中**可真实点击切换**，而传了 `collapsed` 的示例是受控但无监听 ⇒ 静态快照。⚠️ **未开启 `toggleable` 时忽略 `collapsed`**（避免「没有切换按钮却已收起」的死锁）。**与官方三处有意差异**：①**不提供 `toggleButtonProps`**（`object` 型 props 袋无法在本项目既宽又安全地类型化），同一需求由官方同样存在的 `togglebutton` 插槽覆盖（可放任意共享 `Button`）；②`header` 插槽作用域**只给 `{ collapsed }`**（官方的 `id` / `class` 分别对应其内部 id 与图标字体类名，本项目用 `IconWrapper` + IconKey，提供会产生误导）；③**折叠用 `v-show` 瞬时收起 + 切换图标 0.12s 旋转，不做官方的高度折叠动画**（不用 JS 测高、不用 `grid-template-rows` 兼容 hack；`v-show` 同时保证内容 DOM 保留、表单状态不丢，且收起后退出 a11y 树与 Tab 序列）。无障碍：切换按钮是共享 `Button` 的纯图标形态 ⇒ 必有 `aria-label`（文案走 `toggleLabel` prop + 中文默认值，可覆盖为调用方 i18n ⇒ **零 i18n 分片改动**）+ `aria-expanded` / `aria-controls`，内容区 `role="region"` + `aria-labelledby` 指向标题；自定义切换按钮请用 `togglebutton` 插槽（作用域含 `toggleCallback` 与 `keydownCallback`，**原生 button 只绑 `toggleCallback`，只有非 button 元素才需 `keydownCallback`**，否则会双触发）。
- **无缝拼接控件**：`InputGroup` + `InputGroupAddon` 把输入框、按钮、下拉、日期与附加项拼成一体化控件（组内零间距、相邻边框 1px 重叠、仅最外侧保留圆角，档位经 `--ig-addon-*` CSS 变量从容器继承）；组内按钮建议用描边外观（`outlined` / `variant="secondary"`），填充态按钮边框为透明，拼接处会呈现实色块；示例默认插槽需渲染多个子组件，故由 `PreviewExample.render` 组装（见下方「清单扩展指南」）。
- **表单标签能力**：`Label` 支持包裹控件建立**原生隐式关联**（`wrapper`，插槽内容直出、不套文本层，避免控件被文本层挤压与样式串染）、**禁用态三入口**（`disabled` prop / 容器 `data-disabled` / 邻近被禁用的兄弟控件）、**必填无障碍**（`required` 的 `*` 对屏幕阅读器隐藏，`required-text` 以视觉隐藏文本播报）。⚠️ 禁用联动的「邻近兜底」仅覆盖**禁用态就在根元素上**的成员（`Switch` 的原生 `button[disabled]`、原生 `input`）；`Input` / `Select` / `DatePicker` 的禁用态加在内部元素上，根元素无 `disabled`，**需由包装层显式标记 `data-disabled`**。另：`FormField` 的 `labelId` 可为内部 `<label>` 指定 id，供控件用 `aria-labelledby` 建立原生关联（不传时输出完全不变，`Select` 已用其建立「可见标签 ↔ 组合框」关联）。
- **内联列表选择**：`Listbox` 在页面上平铺选项列表（与下拉形态的 `Select` 互补），支持单选 / 多选（`multiple`，多选时 `v-model` 为数组）、复选指示（`checkbox`，每项常驻方框）与勾选指示（`checkmark`，配 `highlightOnSelect: false` 可做到「仅勾选、不高亮整行」）、内置筛选（复用 `Input`，按 `label` 与 `keywords` 双字段匹配）、单项禁用（`option.disabled`）、整体禁用与 `error` 校验态；无数据与筛选无结果共用 `emptyText`。⚠️ 键盘范围**只含基础键**（Tab / ↑↓ / Enter / Space / Home / End），不做 Shift/Ctrl 组合键、字符定位与虚拟滚动，也不做选项分组与字段映射。指示器是**纯装饰元素**（`role="option"` 内不得嵌套可交互元素，故刻意不复用 `Checkbox`；勾选图标复用 `IconWrapper`）。
- **下拉选择的无障碍与键盘**：`Select` 对外暴露 `role="combobox"`（`aria-haspopup` / `aria-expanded` / `aria-controls` / `aria-activedescendant` / `aria-disabled`），下拉面板为 `role="listbox"`、每个选项为 `role="option"`（带 `aria-selected` / `aria-disabled`）、分组为 `role="group"`（`aria-labelledby` 指向可见分组标题）。有关联可见标签时控件的无障碍名称自动取自该标签（组件经 `FormField` 的 `labelId` 建立关联）；无可见标签时用 `ariaLabel` / `ariaLabelledby` 显式指定，清除按钮的名称用 `clearLabel`（默认「清除」）。键盘行为：Tab 进入 → ↑↓ 移动并把激活项**滚动入视野** → Enter/Space 选中 → Esc 关闭且**焦点回到选择框**；打开面板时优先定位到当前已选项（无已选项时 ↓ 落首项、↑ 落末项）；`filterable` 时筛选框内 ↑↓/Enter/Esc 同样生效（Space 与可打印字符正常输入）。列表容器恒常渲染（无匹配时也保留 `role="listbox"` 落点），筛选框在无匹配结果时不再消失。
- **滑块能力**：`Slider` 基于原生 `input[type=range]`，键盘（←→↑↓ / Home / End / PageUp / PageDown）与 `role="slider"` + `aria-valuemin|valuemax|valuenow` 全部由浏览器原生提供，组件只补 `aria-labelledby`（有可见标签时自动关联，经 `FormField` 的 `labelId`）与 `aria-readonly`。`showValue` 在轨道右侧显示当前值，`showMinMax` 在轨道**下方两侧**显示最小/最大值；两者共用 `formatValue`（极值也走同一格式化函数）。`readonly` 会拦截拖拽与全部改值按键（原生 range 不支持 `readonly`，组件内自行把 DOM 值回滚到受控值）；`disabled` 交给原生属性。四档尺寸经根类输出 `--si-slider-track-h` / `--si-slider-thumb-size` 单点驱动轨道与拇指，档位值为 3/4/6/8px 与 10/14/16/18px。
- **代码复制**：每个示例卡片对应一段可复制的 Vue 用法代码（`copyToClipboard` + 已复制反馈）。
- **导航与检索**：左侧锚点导航（按组件分区跳转）+ 组件名搜索过滤，兼容超长内容滚动。
- **组件尺寸档位**：头部 XS / S / M / L 四档切换，作用于所有支持 `size` 的组件（`PreviewGroup.sizeable` 标记的 Button / ToggleButton / Input / Textarea / InputGroup / FormField / Label / Select / Listbox / Switch / Checkbox / RadioButton / DatePicker / Slider / SpeedDial / Paginator / Timeline / Tabs / Toolbar / Tag / Badge / Avatar / Card / ConfirmDialog / ConfirmPopup / Dialog / Drawer / Tooltip / FileUpload）——渲染时向**未显式指定 `size`** 的示例注入全局档位；显式指定 `size` 的示例（尺寸对比用例）保持原样，避免标题与实际渲染不符。选择经 `TypedStorage` 持久化。
  - 四档字号阶梯为 **10 / 12 / 14 / 16px**（`$font-size-2xs` / `$font-size-xs` / `$font-size-sm` / `$font-size-base`），切档后文字大小可辨；Card 标题四档同步为 10/12/14/16、副标题为 10/10/12/14，Switch 标签随档位变化，Checkbox 标签随档位变化（方框与指示器图标同步为 14/16/18/20px 与 10/12/14/16px），RadioButton 标签随档位变化（圆框同步为 14/16/18/20px，内部圆点按 50% 等比），Textarea 的字号与内边距随档位变化（2px 6px / 2px 6px / 6px 10px / 10px 14px），Slider 的当前值与极值标签随档位变化（轨道与拇指同步为 3/4/6/8px 与 10/14/16/18px），DatePicker 的输入框与日历单元格字号同阶变化（单元格边长 22/24/28/32px），Select 的 XS 档下拉内部（筛选框/空态/分组标题）一并降为 10px，Timeline 的事件文字随档位变化（10/12/14/16px，节点直径与连接线宽恒定），Tabs 的标签与面板字号随档位变化（10/12/14/16px，标签水平内边距与面板上边距同步收放，下划线厚度与标签栏分隔线恒定），Toolbar 的工具栏字号与几何量随档位变化（字号 10/12/14/16、上下内边距 3/4/4/5px、左右内边距 4/8/12/16px、最小高度 28/36/44/54px、段间距 6/8/8/12px；边框宽度与圆角恒定），Dialog 的弹窗宽度、内边距与基准字号随档位变化（宽度 320/400/520/680px、字号 10/12/14/16px；`max-height: 80vh`、1px 描边与圆角恒定），Drawer 的贴合边延伸量、内边距与基准字号随档位变化（延伸量 320/400/520/680px、字号 10/12/14/16px；**`left` / `right` 落在宽度、`top` / `bottom` 落在高度**，1px 描边与朝内圆角恒定），Tooltip 的气泡字号与内边距随档位变化（10/12/14/16px，**气泡宽度随内容自适应、不随档位变化**），FileUpload 的字号、各段内边距与段间距随档位变化（10/12/14/16px；拖拽区图标同步为 32/40px，**列表高度上限同步为 132/168/200/240px**，**移除按钮尺寸同步为 20/22/24/26px**，缩略图边长由 `previewWidth` 独立控制且**占位框与图片同源**）。规则见 `AGENTS_STYLE.md` § 组件 size 档位字号阶梯。
  - 注：Chart（`size` 为预设像素宽高，大档会撑破卡片）、IconWrapper（`size` 为像素数）、Loader（无 props）、Divider（无 `size` prop）、Panel（无 `size` prop）、Splitter / SplitterPanel（无 `size` prop）不参与档位切换；图标尺寸不随档位缩放。
- **明暗适配**：不自行造主题——面板与组件全部消费思源 `--b3-theme-*` 变量，明暗随思源主题自动切换（Chart 经自身 `theme: "auto"` 同样跟随）。
- **单选组的快照局限**：`RadioButton` 是「多实例互相约束」的组件（同组共享同一个 `v-model` 与 `name`，各实例 `value` 不同），单卡片快照只能呈现一个实例，因此分区内快照用于确认外观与状态；组用法见 `previewData/radioButton.ts` 中「单选组（同 v-model + 同 name）」示例的 `code` 模板。

## 弹层类组件的预览沙箱

`ConfirmDialog` 这类弹层组件的遮罩是 `position: fixed; inset: 0`，直接放进快照会铺满整个预览窗口。`styles/PreviewSection.scss` 的 `.cp-card__stage` 因此设置 `position: relative`，并把舞台内的 `.si-confirm-mask` 覆盖为 `position: absolute; z-index: 1` —— **仅作用于预览沙箱，不改组件本体**（组件在真实调用处仍是全屏固定弹层）。后续新增其它弹层类共享组件时，在同一处追加对应遮罩类名即可。

`Dialog` 同为 `position: fixed` 遮罩 + 卡片，按同一机制覆盖为 `position: absolute`（`.si-dialog-mask.si-dialog-mask`）；又因为它是三段结构、比确认框更高，新增 `.cp-card__stage--dialog` 给足舞台高度（`PreviewSection.vue` 按 `group.id === 'dialog'` 判定），并在该高度类内把卡片 `max-height` 收敛为 `100%` —— 真实调用处的上限是 `80vh`，沙箱内收敛后「长内容」示例演示的才是**内容区内部滚动**，而不是整块被 `.cp-card` 的 `overflow: hidden` 裁掉。卡片宽度无需覆盖：组件侧 `max-width: 100%` 已把四档宽度收敛到舞台宽度（因此沙箱内的档位差异主要体现在字号与内边距）。

`Drawer` 同样是 `position: fixed` 遮罩 + 卡片，按同一机制覆盖为 `position: absolute`（`.si-drawer-mask.si-drawer-mask`），并新增 `.cp-card__stage--drawer` 给足舞台高度（`PreviewSection.vue` 按 `group.id === 'drawer'` 判定）。该高度类内把卡片 `max-width` / `max-height` 一并收敛为 `100%`：左右抽屉本就靠 `max-width` 收敛，而**上下抽屉**的 `height` 取档位延伸量（320～680px），若不在沙箱内收敛就会溢出舞台被 `.cp-card` 的 `overflow: hidden` 裁掉 —— 收敛后「长内容」示例演示的才是内容区内部滚动。⚠️ 抽屉默认贴死视口边缘，沙箱内因遮罩已改为相对舞台定位，遂改为贴死**舞台**对应边，这也正是各方向示例的目视检查点。

`SpeedDial` 默认 `position: fixed` 悬浮于视口角落（角落档位靠 `right/bottom` 定位），同样按上述机制在舞台内覆盖为 `position: absolute`（`right/bottom` 遂改为相对舞台生效），并新增 `.cp-card__stage--speeddial` 给足高度 —— 因为 `.cp-card` 是 `overflow: hidden`，展开后的动作会超出舞台被裁掉。该高度类由 `PreviewSection.vue` 按 `group.id === 'speedDial'` 判定，追加其它需要特殊舞台尺寸的组件时照此办理。

`ConfirmPopup` 也是 `position: fixed`，但它是**贴锚点的小气泡**而不是铺满视口 ⇒ **不需要遮罩覆盖**：卡片 `overflow: hidden` 裁不到它（fixed 元素不受祖先 `overflow` 裁剪，除非祖先带 `transform` / `filter`），代价是气泡可能压到相邻卡片上（属预期，便于观察定位是否准确）。若后续某组件的浮层确需限制在舞台内，再按 `--loader` / `--speeddial` 范式追加高度类或覆盖定位。

`Tooltip` 与 `ConfirmPopup` **完全同类**（贴锚点小气泡、`fixed` + 视口坐标）⇒ 同样**不做任何定位覆盖**。⚠️ **切勿**照 `Dialog` / `Drawer` 的范式把它改成 `position: absolute` —— 那两个组件的 `top` / `left` 由**模板类**驱动（改为 absolute 后相对舞台仍正确），而 Tooltip 的 `top` / `left` 是 **JS 按真实视口算出的坐标**，改成 absolute 会相对舞台再偏移一次，气泡直接飞出卡片。气泡压到相邻卡片上属预期（同 `ConfirmPopup`）。

## 事件契约（无法在快照中呈现，在此登记）

快照只能展示初始 props 的渲染结果，**事件语义**无法呈现。约定语义特殊（非纯 `v-model`）的事件在此登记，改动时同步维护：

| 组件 | 事件 | 语义 |
| --- | --- | --- |
| `ColorField` | `update:modelValue` | 实时值：hex 文本框逐字输入时持续触发，仅更新内存 |
| `ColorField` | `change` | 提交信号：文本框 blur/回车、或在调色板选色后触发；消费方据此落盘，避免逐字写盘 |
| `Slider` | `update:modelValue` / `change` | 同上模式：拖动过程只发 `update:modelValue`，松手才发 `change` |
| `Input` | `update:modelValue` / `change` | 同上模式：原生 `input` / `change` 分别转发 |
| `Textarea` | `update:modelValue` / `change` | 同上模式：原生 `input` / `change` 分别转发；另有 `input` / `focus` / `blur` / `keydown` 事件透传 |
| `ToggleButton` | `update:modelValue` / `change` / `click` | 点击即同时派发 `update:modelValue`（翻转后的布尔值）与 `change`（提交信号），随后派发原生 `click` 事件；`disabled` 时三者均不派发 |
| `SpeedDial` | `update:visible` / `show` / `hide` | 开合状态变更：`update:visible` 承载新值（支持 `v-model:visible`），并按新值派发 `show` 或 `hide`；不传 `visible` 时组件也可独立开合（内部兜底状态） |
| `SpeedDial` | `select` / `click` | `select(action, event)` 在点击某个动作时派发（同时会先调用该项的 `onClick`，随后收起）；`click(event)` 是主按钮的原生点击；另有 `focus` / `blur` 转发主按钮焦点事件 |
| `Paginator` | `update:page` / `update:rows` / `change` | `update:page`（1 基新页码）与 `update:rows`（每页条数）为实时跟随；`change` 为一次性提交信号，载荷 `{ page, rows, total, totalPages, first, last }`。**`rows` 变更会在同一次交互中先派发 `update:rows`、再（必要时）派发 `update:page(1)`，最后派发一次 `change`** —— 消费方按 `change` 落盘即可 |
| `DatePicker` | `update:modelValue` / `change` | 同日提交：选中、手输解析、清除时两者同时触发（无「实时跟随」阶段）；另有 `visibleChange`（弹层开合）、`viewChange`（视图切换）、`clear` |
| `ConfirmDialog` | `confirm` / `cancel` | 确认按钮触发 `confirm`（**不自动关闭**，由父组件决定关闭时机，便于异步操作）；取消（取消按钮 / 右上角关闭按钮 / 遮罩点关 / Esc）触发 `cancel` 并同时派发 `update:visible(false)`，故支持 `v-model:visible` |
| `ConfirmPopup` | `confirm` / `cancel` | 与 `ConfirmDialog` 同语义；取消来源为取消按钮 / 点组件与锚点之外 / Esc（`dismissable` 与 `closeOnEscape` 可分别关闭） |
| `Dialog` | `update:visible` / `show` / `hide` / `after-hide` | 关闭请求（关闭按钮 / Esc / 遮罩点关）一律派发 `update:visible(false)`，由调用方决定最终状态（故支持 `v-model:visible`）；`show` / `hide` / `after-hide` 分别对应过渡的**进入 / 离开 / 离开完成**（官方时机），可据此做「动画结束再复原或销毁」一类收尾。`Dialog` 无 `confirm` / `cancel` 语义（那是 `ConfirmDialog` / `ConfirmPopup` 的内容段事件） |
| `Card` | `click` | 仅在 `clickable` 为真且非 `disabled` / `loading` 时派发（载荷为原生 `MouseEvent`）；`disabled` / `loading` 时静默不派发 |
| `Drawer` | `update:visible` / `show` / `hide` / `after-hide` | 与 `Dialog` **同语义同时机**：关闭请求（关闭按钮 / Esc / 遮罩点关）一律派发 `update:visible(false)`，由调用方决定最终状态（故支持 `v-model:visible`）；`show` / `hide` / `after-hide` 分别对应过渡的**进入 / 离开 / 离开完成**。⚠️ 不做官方 `before-hide` / `after-show`（时机分别与 `hide` / `show` 重合，库内 `Dialog` 已裁剪，保持一致）。`Drawer` 无 `confirm` / `cancel` 语义 |
| `Tooltip` | `update:visible` / `show` / `hide` | 显示 / 隐藏时派发：`update:visible` 承载新值（配 `v-model:visible`；**受控时组件不会自行改状态**，只派发事件等调用方回写），`show` / `hide` 按新值派发。⚠️ 非受控模式下（不传 `visible`）同样派发，便于「首次显示时懒加载内容」一类副作用。`showDelay` / `hideDelay` 只影响派发时机 |
| `FileUpload` | `select` | 文件**通过校验并被加入队列**时派发：`(files: File[], originalEvent: Event \| null)`。⚠️ 被拒绝的文件**不在**载荷中（它们走 `invalid`）；选择与拖拽两条路径同语义，`originalEvent` 为 `null` 表示非事件触发（如程序化调用） |
| `FileUpload` | `remove` | 单个文件被移除：`(file, files)` —— 第二个参数是**移除后的剩余队列**，便于调用方直接覆盖本地副本 |
| `FileUpload` | `clear` | 队列被清空（取消按钮 / `clear()` 方法）时派发，无载荷 |
| `FileUpload` | `upload` | 点击上传按钮时派发，载荷为**当时的完整队列**。⚠️ **组件不做网络请求**（不做官方 `url` / `auto` / `customUpload`），由调用方接管；`uploading` / `progress` 需由调用方回报 |
| `FileUpload` | `invalid` | 校验失败时派发（**即使部分文件通过也会派发**），载荷为全部失败项数组（`{ fileName, reason: "size" \| "type" \| "limit", message }`，`message` 已插值可直接渲染）。⚠️ 一次选择中失败的每一项各占一条 |
| `Panel` | `update:collapsed` | 折叠状态变更的新值（`boolean`），**受控与非受控两种模式下都会派发**；支持 `v-model:collapsed` |
| `Panel` | `toggle` | 切换时派发的完整事件：`{ originalEvent: Event, value: boolean }`；与 `update:collapsed` 同时派发，顺序为先 `update:collapsed` 后 `toggle` |
| `Tabs` | `update:value` | 激活标签变更的新值（配 `v-model:value`）；**仅值实际变化时派发**（幂等，点击已激活标签不会重复触发），**非受控模式（不传 `value`）下同样派发**。`Tab` / `TabList` / `TabPanels` / `TabPanel` 均**无自有事件** |

> 通用建议：需要「实时跟随 + 一次性落盘」的交互（滑块、颜色、文本输入），消费方应监听 `update:modelValue` 做内存更新、监听 `change` 做持久化，可避免写放大与提示刷屏。

## 清单扩展指南

1. 在 `previewData/` 对应分组文件（或新文件）追加 `PreviewGroup` / 往 `examples` 添加 `PreviewExample`：
   - `title`：示例标题（中文）
   - `props`：透传给组件的 props 组合
   - `slotText`：默认插槽文本（需要插槽的组件）
   - `render`：复合示例的默认插槽渲染函数（可选，存在时优先于 `slotText`；入参为注入全局档位后的实际渲染 props，返回 VNode 或 VNode[]；用于 `InputGroup` 这类插槽内需放多个子组件的示例）。⚠️ 返回值是**目标组件的子节点**，不是组件自身 —— `Tabs` 五件套即用它把 `TabList` / `TabPanels` 交给 `Tabs`（见 `previewData/tabs.ts`）
   - `slots`：具名 / 作用域插槽渲染（可选），形如 `{ content: (slotProps, exampleProps) => VNode }`；键为插槽名，工厂首参是该插槽的作用域参数、**第二参是注入全局档位后的实际渲染 props**（插槽内放了共享控件时用它取 `exampleProps.size`，使内部控件与容器同档 —— `Toolbar` 即此用法）。**工厂可能被多次调用（列表类组件每个事件一次），必须在工厂内部新建 VNode**，不可在数据文件顶层构造后复用同一实例
   - `code`：与 props 对应的可复制 Vue 模板代码
2. `previewData/index.ts` 聚合后导出 `PREVIEW_GROUPS`（index.vue 遍历渲染）。
3. 面板 UI 文案走 i18n 分片（`componentPreview` 键），新增文案需 zh_CN / en_US 同步。
4. 新增支持尺寸档位的组件：在该 `PreviewGroup` 上标记 `sizeable: true`（渲染时会注入全局尺寸档位）；增删档位改 `types/size.ts` 的 `COMPONENT_SIZES` 与 i18n 的 `sizeXsmall` 等键。
5. 新增/修改共享组件的 props、行为、**具名插槽**或**事件契约**后，必须同步 `previewData/*.ts` 与本文档（见上方「具名插槽」表与「事件契约」表）。

> 约定：`Label` 的 `required` 只负责**视觉标记 + 屏幕阅读器替代文本**（`*` 已 `aria-hidden`、`required-text` 视觉隐藏播报），**控件侧仍需自行声明 `required` / `aria-required`** —— 有意不在 `<label>` 上输出 `aria-required`（该属性属输入类角色，放在标签元素上是无效 ARIA）。
